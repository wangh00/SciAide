# 网络、项目浏览器与 MCP

更新：2026-11-04。本文描述当前实现及限制，不承诺外部站点、代理或模型服务始终可用。整体权限边界见 [安全边界](threat-model.md)。

## 代理配置

设置页集中模型/API、搜索、Skill、MCP、网络与代理。默认直连，不修改操作系统代理。

- 优先级：模块覆盖 → 应用全局 → 直连；模块可继承、强制直连或自定义 HTTP/HTTPS/SOCKS5 代理，当前不提供代理账号密码配置。
- 保存有版本检查，避免旧窗口覆盖新配置；代理失败不自动改为直连。
- 模型/Embedding、搜索与网页、文献下载、Python/依赖、Skill Git、MCP、浏览器各有相应模块。
- 新 HTTP 请求可更新配置；已开始的下载/浏览器操作固定配置。已运行 Python Kernel 或 MCP 子进程需重启取得新环境。
- 仅能约束本应用 Adapter 和提供给子进程的代理配置；忽略环境变量、自建连接的第三方程序不保证被接管。

代码：[internal/network](../internal/network/)、[browserenv](../internal/app/browserenv/)、[browserhttp](../internal/browserhttp/)。

## 项目浏览器

在项目的托管 Python 环境中显式安装浏览器环境，当前固定 `cloakbrowser[geoip]==0.5.9`。Python 包放在项目 `.sciaide/python`，浏览器、GeoIP、运行脚本、缓存和临时目录放在 `.sciaide/browser`；不使用个人浏览器资料，也不修改外部 Python 环境。

- 安装使用“Python 与依赖安装”代理；主动网页访问使用“浏览器访问”代理。
- 文献质询复用**该次文献下载**的出口，不擅自切换浏览器模块代理。
- 同项目不并发操作浏览器，跨项目排队可取消；Windows 取消回收受管进程树。
- 更新通过显式安装/修复，不在后台悄悄升级浏览器资源。
- 工具名为 `builtin.browser.open`，模型侧可能显示适配后的名称。新路线可冻结该定义；旧路线不会仅因升级被自动扩权。

**能力限制**：当前是浏览器验证后的 HTTP 网页文本提取，不是完整点击/表单/动态 DOM 工作台，不保证所有 Cloudflare 站点可访问。

## 文献访问与 Cookie

HTTP 403 且 `Cf-Mitigated: challenge` 才尝试一次浏览器兜底；失败进入冷却，不无限切换请求。下载仍需满足原 PDF 类型、大小和内容检查。

浏览器与 Go 下载侧核验出口，使用同 UA 和域隔离 CookieJar；代理配置变化时拒绝复用 Cookie。Cookie 不进入模型上下文或普通审计；私有临时结果正常结束/取消时清理，异常断电仍可能留下临时文件。

需要固定出口或粘性代理；每连接轮换 IP 的代理无法靠一次探测保证下一连接一致。出口核验不可用时不降低检查。入口限制不等于对子请求、DNS 和代理建立了强网络沙箱。

取得 PDF **不等于**当前任务已采用它。后续仍要纳入、解析/索引、签发当前可用证据、确认并更新报告；现有知识链支持这些步骤，但任意对话新搜到的 URL 自动回填旧冻结路线并未通用闭合。不能因为 Cookie 成功就宣称报告的引用已经更新。

## 文献来源与能力契约

文献题录检索与全网搜索继续分开：前者保存可追溯题录、查询快照并进入材料/引用链；网页和搜索结果不因被找到就成为已核读的科研证据。

- 固定能力以 [researchsources/catalog.go](../internal/researchsources/catalog.go) 为唯一代码契约，连接器、工具来源枚举、年份能力和固定网络权限从这里派生。目录含 OpenAlex、Crossref、arXiv、PubMed、Europe PMC、Semantic Scholar、ERIC、CORE。普通/手工调用省略 `sourceIds` 时仍选前七源，CORE 必须显式选择，手工检索不默认勾选 CORE。
- **新科研分配契约**：新编译规划 `dynamic-literature-query-expansion-v6` 必填 `retrievalProfile`、`sourceRationale` 和 `sourceIds`；非空数组为完整显式集合，`[]` 为明确采用学科默认配置，不以理由中的数据库名称或 `providerQueries` 代替选源。宿主把已接受规划中的来源冻结并传给原检索工具 v9，续检索可取明确集合的子集、不能扩围；新版本缺失或损坏选源时停止，不回退五库等默认配置，改变集合须重新规划。配置及优先顺序以 [retrieval_plan.go](../internal/app/research/retrieval_plan.go) 为准，CORE 仍须显式选择；旧 v3/v4/v5 冻结路线不热升级。**本轮确定性保证的是结构化选择的传递和执行，不是任意自然语言来源限制的自动语义识别**：模型是否正确把用户要求提取成集合仍须核验，不能仅凭填写了字段声称已遵守“三库”要求。
- **来源请求预算**：有领域配置的每次检索工具调用最多 14 次来源 HTTP 尝试，含连接器重试和来源重定向；不是全任务调用/金额/token 限额，也不包含代理 CONNECT、DNS、后续正文导入或模型请求。PubMed 槽基准为 esearch+efetch 的 2 次，其余来源为 1 次。按声明顺序执行并为后续来源槽保留基准总额，前源重试不能侵占；基准不是内部每个子步骤必成功的保证，PubMed 重试后可能没有足够槽额度获取 efetch，必须明确预算未完成而非无文献。不因空结果/冷却自动新建检索槽或翻页。
- **不可重放的预算传输**：预算检索专用标准 TLS / HTTP/1.1、新连接模式，明确不模拟浏览器 TLS 指纹、不启用 HTTP/2，避免底层连接复用/HTTP2 透明重发绕过计数；仍复用模块代理、证书核验、取消及固定主机/端口检查。普通接口和 PDF 的浏览器传输不改。未知注入 transport 没有显式单次契约就拒绝，不静默走不可计数通道。该模式可能改变延迟和来源兼容性，不能把受控或少量公开测试扩大为所有来源/网络已验收。
- **计划与证据保全**：领域模式不逐条自动补全缺失摘要；必要的后续 fetch/导入仍单独走原权限。每条完整查询仍保存一条多来源历史，不因串行槽位拆成十余条同文历史；原式与实际来源投影分开保存。计划边界、逐槽额度/用量、本地预算拒绝和真实来源失败写入原工具结果及筛选记录；未安排不冒充来源故障，预算拒绝不冒充上游不可用。有限检索仍由原科学覆盖判断和独立审查决定是否足够，程序不代为批准。
- ERIC 保留教育学段、主题词、文献类型与同行评审标记；标记是来源属性，不是科学质量批准。只有 API 明确给出 `e_fulltextauth=1` 才构造固定 `files.eric.ed.gov` PDF 目标，仍须通过原下载、类型/大小、解析及索引校验。OpenAlex 不继承这项新增主机权限。
- CORE 当前仅为可选的匿名元数据检索：保存摘要、题录和许可字段，不保存或采用 `fullText` 字段作为正文、不把访问提示当正文，不启用发现重定向或任意仓库 PDF 下载。没有注册账户、配置新密钥或批准额外全文/再分发许可；后续接入须另行核对 [CORE 文档](https://api.core.ac.uk/docs/v3) 与 [使用条款](https://core.ac.uk/terms)。ERIC 官方契约见 [API 说明](https://eric.ed.gov/?api)。
- 两源的年份使用出版年原生过滤。鉴权拒绝、限流、格式损坏与合法空结果分开；429 不自动重试，后续不同查询也遵守来源冷却和有效服务端窗口。窗口缺失时只做短暂本地暂停，不宣称真实配额已重置；不可读的 5xx 响应体不新增重试。
- **统一响应缓存入口**：[文献客户端](../internal/research/connectors/client.go)的 `getJSON` 在类型签名上要求来源校验器；原始字节请求启用缓存时也必须传入语义校验，不能只检查 HTTP 200 或语法便缓存。解码完整性、必要结果包、已支持的来源条件、请求绑定与记录可用性均在新响应写缓存前及缓存命中时执行。已有坏缓存明确失败，只剔除相同内容的值，不当次补发；下一次显式检索仍受原预算/冷却控制，有效缓存照常复用。不从错误文字猜限流/余额，也不追改旧冻结历史。
- **检索页、批量与分页**：七个 JSON 检索集合缺失/null 均为 `invalid_data`；非空页须在实际转换/截取窗口内至少有同一条可用记录，不能借用别条字段或窗口外有效项。arXiv 同样区分原始空 feed 与非空但没有可用项。PubMed 的 ESearch PMID 必须有效且规范身份不重复；EFetch 在缓存前检查完整 XML、精确且无重复的请求批量，并按 ESearch 顺序返回，不把缺失文章降格为空成功。[ERIC](../internal/research/connectors/eric.go)/[CORE](../internal/research/connectors/core.go) 保留既有两项计数矛盾检查，不扩大推断；合法零结果及已到/越过总数的空页仍可缓存。Europe PMC 只有还需跨过的非空中间页才要求游标推进，无可用中间页不跳过，最终/合法空页不强求后续游标。偏移、窗口、预期批量/身份及游标上下文由宿主私有字段或闭包绑定，源 JSON 不能覆盖。
- **统一最小身份契约**：[record_contract.go](../internal/app/research/record_contract.go)供检索、单查与 Service 共用：同一条记录须有题名及可取回的源记录 ID，非空来源声明不得被 Service 改写成另一来源。保存的源记录 ID 去首尾空白后最多 512 字符，超长拒绝而非截断；已支持等价形式规范化后也最多 512。arXiv 传输 URL/版本先无损规范化，保存 ID 和 arXiv 标识使用同一上限。来源内按既有 Fetch 等价规则去重、保留第一条原始字段；不透明 ID（含 Semantic Scholar）保留大小写差异，不新增任意别名。真实空页和混合页有效项保持，非空数据全无效必须失败，不自动变成“没有研究”。这只是最小可用性与身份一致性，不认证真实出版物或科学质量。
- **已核实状态与计数边界**：Crossref 若提供 `status` 必须为 `ok`，OpenAlex 若提供非 null 根 `error` 不得同时当成功题录（[Crossref 官方契约](https://github.com/Crossref/rest-api-doc)、[OpenAlex 错误说明](https://help.openalex.org/api/errors/)）；没有按任意来源的相似字段名猜业务失败，也不猜 PubMed JSON error/errorlist/warnings 的全部语义。`LimitReached` 仅表示适配器返回条数达到请求窗口，不证明来源已经穷尽、完整召回或独立研究数量。未知提供商 schema/业务计数仍属未核实，不自动补搜、放宽审查或新增来源权限。
- **单条取回身份**：`builtin.research.fetch` 仍按检索返回的来源/记录标识取回，不新增任意提供商标识别名。原 Service 在有损归一化前绑定请求与返回标识，八源在响应缓存前做同一核对；私有预期标识不接受源 JSON 覆盖，缺标识/题名、错身份及歧义多条明确 `invalid_data`。等价形式及保守的 opaque ID 比较以 [fetch_validation.go](../internal/app/research/fetch_validation.go) 为准；arXiv 沿用版本无关身份，不保证精确修订版。PubMed/arXiv 在缓存前检查完整 XML 文档的单根与根外文本边界，允许文首一次 UTF-8 BOM、合法空白/注释/普通 PI，不等于完整 XML/提供商 schema 验收。四个集合式单查的合法空包仍缓存，随后返回 `not_found`；HTTP 404 与数据错误分开，旧错身份缓存失败后剔除且不当次补发。摘要补全使用同一身份规则，保留原检索 ID/题名与独立 DOI 冲突保护；这些检查不证明文献真实性，也不放宽材料权限、来源预算或科学审查。
- 完整规范化来源属性保存在原查询/来源快照；筛选、选择卡、材料预览和导入回执使用目的专用的合法 JSON 视图，并披露省略、总数和完整哈希。候选回读按原冻结快照验哈希，不能以最新书目替换；长题名交接同样明确标记视图，完整题名仍在候选中。省略不等于字段不存在，题录不能混充 PDF 原文或升级证据等级。
- **来源查询编译与审计**：新检索使用 `source-query-v1`，一次编译结果供连接器派发和审计使用，逐来源绑定逻辑原式、来源输入式、有效式、来源表达式、实际语法模式与输入来源。规划表达式不能绕过排名接口转换，也不能以“来自规划”覆盖实际语法模式。具体实现见 [source_query.go](../internal/app/research/source_query.go)。
- **排名投影的边界**：Crossref 与 Semantic Scholar 当前基础搜索端点使用排名关键词，不能宣称等价于布尔式或必然扩大召回（[Crossref 官方说明](https://community.crossref.org/t/advanced-set-boolean-operators/4596)、[Semantic Scholar 基础搜索文档](https://api.semanticscholar.org/api-docs)）。[转换器](../internal/app/research/query_projection.go)保留词内标点，按完整表达式处理否定组和字段后缀，记录未执行的布尔、否定、字段、短语约束；不支持的字段方言、引号/括号错误、仅排除项和显式空规划式在本地返回不可重试的 `invalid_query`，不调用该来源、不冒充空结果或接口不可用。限制清单只描述输入式的语法转换，空清单不证明规划式与逻辑原式语义一致，仍由原科学筛选/审查核对。
- **年份与历史绑定**：ERIC、Europe PMC、CORE 的查询内出版年过滤使用[共享格式化](../internal/app/research/provider_year_query.go)，审计保存拼接后的来源表达式；其他来源的独立年份参数仍分开记录。`providerQuery` 是编译表达式，兼容字段 `yearFilterApplied` 仅表示过滤参数已构造；它们不证明本次已发 HTTP、未命中缓存或上游执行了过滤，不能当完整请求 URL/请求回执。新来源状态在发现页和报告附录展示这些冻结字段，不回填或重编旧记录。新失败/预算键使用逐逻辑式、来源输入、年份和偏移的完整身份，避免相同投影互相清除；历史有损键保留原行为，不从新成功猜补旧归属或宣称旧失败已解决，旧碰撞无法据现有字段恢复。没有新权限、科学自动批准或额外请求。
- **身份归组与待核实线索**：新查询采用 `record-grouping-v2`，只允许经形状检查、无共享种类取值冲突的强标识自动归组；不再以题名/年份自动归并，来源记录 ID 按精确大小写保留。强标识检查不证明已注册或可解析；规则及历史 v1 的真实方法只以 [record_grouping.go](../internal/app/research/record_grouping.go) 为准。冲突判定保存总命中数及有限、足以证明分支的见证，不枚举平方级全部候选关系。
- **线索不代替科学判断**：`record-identity-hints-v1` 按 [record_identity.go](../internal/app/research/record_identity.go) 的固定规则，仅对新查询的规范化题录生成疑似同文、版本、伴随材料及标识冲突提示，类型只来自明确字段/题名前缀，不依据机构中的大学名称推断样本人群。全部待核实，不自动纳入/排除、批准结论或调整独立研究数；没有提示不证明独立，未找到主文不造主文。只在同一查询内生成关联；跨查询读取合并已保存的 scope 清单，不补造跨查询关系或冒充完整关系去重并集。
- **线索边界与指纹**：每 scope/固定类型最多两条见证，并记录全部检测数、类型数、源记录绑定和派生流 SHA；省略的是派生关系清单，不删除原题录。模型预览最多两条类型/关系见证，冲突优先且类型总数可见；导入使用更小概览，综合/审查保留有界导航和省略说明。视图内容 SHA 标识可由已发 `queryIds` 重构的有界清单，并非任一查询 JSON 或全部省略关系的字节哈希。新候选内容指纹绑定自身来源记录、排除可重映射的本地候选 ID，归档恢复同步映射导航 ID；旧指纹不重签、不静默升级。发现页/选择卡目前展示来源号与候选 ID，不承诺跨页点击定位。旧查询不回填，原材料、冻结历史与权限不变。
- 权限/Schema 变化使用新工具版本，旧冻结路线不热扩权。旧在途计划如遇工具定义变化，应显式重新保存/校验当前计划；旧完成阶段、材料和历史不重写，不自动恢复正式任务。当前验证范围只见 [开发进度](PROGRESS.md#4-验证结果与边界)。

## 网页读取与 Fake-IP

- 显式模块代理优先，其次继承全局；有代理时不走直连 DoH 兜底。
- 未配置显式代理且 DNS 解析为 `198.18.0.0/15` 时，网页读取可向固定 IP 的 Cloudflare/Google DoH 查询公网 A 记录，保留 Host/SNI 和 TLS 证书检查，再复核目标地址。
- DoH 只发送域名，不发送路径、Cookie、Key 或正文，不改变系统 DNS/TUN。字面 Fake-IP、私网/本机地址和不安全重定向不因此放行。
- 不保证所有 TUN 分流或 IPv6-only 网站可用；失败时应配置实际 HTTP/SOCKS 代理端口。
- 聊天“联网”开关冻结到该 Run，控制内置搜索/网页/浏览器工具暴露；不是对 Python/Shell/MCP 的 OS 断网，不能借此承诺所有任务离线。

## MCP 连接与按需发现

支持 stdio 与 Streamable HTTP。保存配置不立即连接；启用且受信任的配置可勾选“启动 SciAide 时自动连接”，桌面启动后台连接一次，单台失败不阻塞窗口，不循环重试。未勾选的配置仍需手动连接；上次 ready 不被当作活连接。Resources/Prompts 的发现不等于自动加载正文。

普通聊天链：

```text
builtin.mcp.list：状态和能力概览，不连接、不授权
```

- 发现记录从当前 Run 成功的宿主搜索结果恢复；连接或定义变化后需重新搜索。
- 不把全部 MCP Schema 一开始注入模型；也不能把 Skill 目录当 MCP 工具目录。

## 默认 Exa 搜索（2026-10-16）

- 首次应用数据库迁移 101 时加入 `https://mcp.exa.ai/mcp?tools=web_search_exa`，namespace 为 `exa`，启用、受信任且默认启动连接。仅开放全网搜索，不开启 Agent/付费研究能力；与设置中需 Key 的 Exa REST 搜索独立。
- 免 Key 有额度和限流，不承诺无限免费。连接使用 MCP 模块代理；搜索词会发送给 Exa，结果不签发可信 K 引用。实测官方匿名握手、工具列表、搜索可用，不保证未来配额或外部可用性。
- 初始化只执行一次；删除、禁用、修改后不补回。已有 `exa` 命名空间或同 hosted endpoint 配置则保留用户原设置，不擅自改为信任/自动连接。断开仅影响本次进程；永久关闭需取消自动连接、禁用或删除。
- 普通聊天和科研讨论可通过现有 `builtin.tools.search` 按需加载。预置工具遵守该 Run 的联网开关（连接握手不等于发送搜索）；该开关仍不是任意第三方 MCP 的 OS 断网。
- **范围限制**：冻结科研执行阶段不自动增加 Exa 工具；保留原搜索工具与文献证据链。暂不把易断线、远端可变 Schema 的 MCP 强行冻结为所有阶段的必需依赖，避免 Exa 断开导致整条路线报“定义变化”。阶段级稳定搜索适配另行设计。
- 普通构造、绑定生成和自动化测试不联网；桌面生命周期显式开启启动连接。初始化取消同步撤销底层 HTTP，成功后解除初始化超时与会话绑定。

Jina Reader 暂不接入。后续若启用，适合作为 `builtin.web.open` 的可配置正文提取后端：保留原 URL/提取方式/时间，限制长度、超时、重试和限流；不默认上传私有材料、Cookie、附件，也不替代 PDF 入库与可信证据校验。
