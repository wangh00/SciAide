# 科研能力后续开发计划

> 更新：2026-09-26。本文记录后续开发方向，不代表功能已经实现。
> 当前实现与限制以 CURRENT_STATE.md 和实际运行记录为准。新会话规划科研能力时应同时阅读本文。

## 下一阶段优先级（2026-09-26）

1. **证据更新闭环 + 可重复回归**：先打通一篇摘要补成全文的最小链路：保存新版本、解析索引、签发新引用、标记依赖输出过期、只重跑受影响阶段和审查。旧报告不可变；取消/重启/重复导入可恢复且幂等。用固定文献和数据样例持续回归，而不是只靠真实任务碰问题。
2. **有预算的局部调整**：冻结研究目标和关键约定，不机械冻结全部执行细节。AI 可在获准工具范围内调整检索词、读取材料、修复代码；研究方向、数据外传、费用或工具权限变化需确认。预算耗尽/来源不可用与证据不足分别显示，默认模型请求仍串行。
3. **科研 MCP 能力授权**：自由对话按需发现已完成；科研 AgentStage 尚不能执行通用 MCP。先做阶段级能力选择、精确工具及指纹快照、审批和暂停恢复，再接入发现加载，不直接放宽现有安全规则。工具集合增长后增加定义体积预算及卸载机制。
4. **可核查的数据分析工作台**：优先变量角色、单位、配对/重复测量与关联键确认，再做结果表、独立数值验算及图表局部返修。专业连接器/R 根据真实用户场景试点，不以数量扩展取代质量验证。

建议下一轮只完成第 1 项中的最小闭环，验收后再扩展。阶段结果应可定位到材料版本、引用和受影响报告，并可解释为什么需要重跑。

## 联网第一版实施记录（2026-09-17；后续状态以下述补充及 CURRENT_STATE 为准）

- 通用联网已实现：web_search 与 web_open，百度搜索（默认优先级 1）/Firecrawl/Brave Search/Tavily/Exa 独立 Key、启用与优先级，按序故障回退及 DuckDuckGo 最终兜底。供应商纵向卡片、按需 Key 编辑和独立测试弹窗；Key 与配置存系统凭据库，不返回明文。百度真实 Key 请求已返回 3 条网页结果，不等同学术证据质量验证；超出其 72 加权字符限制的查询显式回退，不静默截断。
- 自由对话、新建科研路线启动器及动态 Agent 阶段可调用；纯 AI Analysis 节点不支持工具，旧任务冻结范围保持不变。普通联网结果直接供推理，不强制文献导入。
- web_open 支持 HTML/纯文本、关键词片段及链接跟进，最多 2 MiB 输入/12000 字正文/40 链接；不执行 JS，不下载 PDF/二进制，不持久缓存页面或签发新研究引用。直连 DNS/重定向校验拒绝非公网地址；可配置可信 HTTP/HTTPS/SOCKS5 代理负责远端 DNS，仍拒绝显式私网目标。后续已新增应用级网络配置，覆盖模型、文献、pip 等模块，局部设置优先；详细边界见 NETWORK_BROWSER.md。
- 回退保留原因：认证/额度/短期限流/网络/解析/验证页面，按类进程内冷却，保存配置清除该来源冷却；不将合法空结果作为故障。官方端点固定，不支持自定义中转地址。
- 全仓 Go、前端 159 项、相关 vet 和设置页面 1280/960 宽度交互检查通过。四 API 根据官方接口与模拟响应验证，未使用真实 Key 付费调用。生产 Go DuckDuckGo 单次返回 3 条；Python 前次验证页仍说明其不稳定。此后已适配 Fake-IP 并完成文档页面真实读取；仍不能宣称所有站点和完整联网闭环实测通过。
- 下文为规划背景，标为待实施的提供商配置基本能力已由上述第一版覆盖；证据再签发闭环、专业数据连接器等仍未完成。

## 1. 目标与约定

### 研究资料库（2026-09-22）

- 资料库只展示用户上传和主动收藏；自动任务材料在文献发现中预览和管理。文献发现的待定、纳入、排除候选均可主动加入资料库，不改变任务筛选/导入状态；未导入候选保存题录摘要，已有材料复用，同内容去重。开题可明确选择主动添加的项目资料，不自动升级摘要为全文。

- 已实现：原始附件主体的资料库，独立标题/备注、分页提取正文、原件导出、持久移出状态与归档恢复；索引仅作内部派生数据。开题选择项目共享资料，文献确认补充任务私有文件；明确选择的文件进入正式导入、索引、证据综合和引用校验。移出资料拒绝新选择，保留历史冻结快照。
- 开题上传明确保存为项目共享，候选阶段上传仅属于本任务。尚无任务创建前的私有草稿附件；不自动提升其他任务资料的共享范围。最多 16 份参考文件，现支持 PDF/DOCX/TXT/Markdown，暂无 DOI/URL/RIS/BibTeX 入口。
- 用户资料保留同 Run 导入来源、附件内容哈希和原文引用快照，不伪造作者、DOI、发表状态或全文等级；导出明确标注用户资料及未核验书目信息。
- 本地资料不自动证明课题相关性，证据综合仍须判断采用、背景或排除。仅选本地资料且路线不需外部检索时，仍保留证据确认链，不强制公共数据库检索。
- 后续：任务前私有草稿、解析状态与原文预览优化、资料使用关系/存储占用与安全清理；补全文后的证据版本更新、依赖失效、报告更新与重新审查按第 4 节推进，不覆盖历史报告。
- 存储沿用项目 `.sciaide` 的对象文件和解析缓存；变更展示层不改变磁盘占用，不能宣称“放进项目目录不占空间”。

面向理解本专业、但不一定会编程的研究者，提供有边界、可核查、失败可恢复的科研辅助流程。

- 不以生成报告或 AI 审查通过作为科学正确性的证明。
- 不推倒现有路线、任务隔离、引用快照、执行审计与自然语言返修架构。
- 在稳定性基础上扩展文献来源、内置联网搜索及可配置 API 服务，包括 Firecrawl 等候选。
- 通用联网独立于文献工具，自由对话与科研各阶段均可按需使用，结果直接供推理，不强制导入知识库；正式用于研究结论的新增依据才进入保存、引用及报告更新闭环。
- 默认保持模型请求串行，不依赖并发提高速度；搜索和材料获取必须有预算、取消与失败恢复。
- 不自动把其他任务的文献发现或科研产物注入新任务；知识库沿用明确的任务和项目共享范围。
- 以下阶段是建议实施顺序，不是已承诺上线日期；具体提供商需核实官方文档、费用与真实接口行为。

## 2. 当前基础与明确缺口

已有按需澄清、路线确认、数据预检、文献筛选与导入、可信证据综合、Python 分析、报告、独立审查、登记前协商返修。

现有公共文献连接器包括 PubMed、Europe PMC、Crossref、OpenAlex、Semantic Scholar、arXiv。常规检索默认一条、最多两条完整检索式，每式每源仅取首页最多 20 条，再去重初筛。这适合范围受限的证据综述，不等于系统综述的全面检索。

当前重点缺口：

- 来源限流、故障和检索覆盖不足需分别处理，不能将接口失败解释为没有证据。
- 已有统一联网入口，但网页/新增全文进入正式证据与报告更新的闭环仍未完成。
- 临时全文核验新增内容尚未形成重新索引、签发引用和刷新报告依赖的完整闭环。
- 来源可追溯不等于主张被原文支持；重复研究、冲突结果与证据级别仍需更可靠地组织。
- 数据研究语义确认与独立数值验算不完整。
- 路线冻结后缺少有预算的局部补证与调整能力。

## 3. 搜索与数据接入分层

### A. 学术文献源

先提高现有来源的可用性，再按学科覆盖和实际增量选择新增来源，不按接口数量衡量质量。

- 增加来源配置与官方 API Key 管理，按提供商能力处理认证、配额、冷却和 Retry-After。
- 核对每个 API 的布尔语法、字段搜索、相关度、日期与文献类型过滤，记录实际 providerQuery。
- 保留每源返回量、失败原因、去重结果和检索时间；故障不触发无休止补搜。
- 评估新增源时比较独有文献、元数据质量、摘要和开放全文覆盖、使用许可、费用及稳定性。

### B. 通用联网搜索与网页获取

建设统一的内置搜索工具适配层，Firecrawl 作为可选提供商之一，不把科研流程绑定在单一厂商上。

最新用户约定：AI 自主搜索知识、公开数据、软件文档等，不限定学术来源，不要求先证明存在证据缺口；支持搜索、打开、页内查找与跟进链接。以下正式证据处理规则不能作为普通联网推理的前置门禁。

#### 提供商优先级与回退（第一版已实现，持续验证）

- 先测试 DuckDuckGo，后续支持 Firecrawl、Brave Search、Tavily、Exa 独立 API Key，与模型供应商解耦。
- 用户设置已启用提供商优先级，按顺序串行调用；不固定 Firecrawl 第一，不并发广播。
- 无 Key 默认 DuckDuckGo；明确额度耗尽或服务不可用时按用户顺序切换后续可用来源，最终 DuckDuckGo 兜底。只有 Firecrawl Key 时，额度耗尽直接回退 DuckDuckGo。
- 按提供商明确错误识别额度耗尽，不能将所有 429 当作没余额；区分认证、短期限流、网络、服务和额度问题，设置相应冷却/恢复机制，避免重复撞失败来源。
- 合法空结果不是服务故障，不自动遍历全部提供商；取消停止整条回退链。记录实际来源和切换原因，密钥绝不跨提供商转发。
- DuckDuckGo 验证码、429 和无法解析页面须报告不可用，不能伪装零匹配或保证兜底成功。

#### DuckDuckGo 测试记录（2026-09-17）

- 前轮 HTML 两个英文查询成功，各 10 条；随后中文及 Lite 查询返回 HTTP 202 验证页，不能据此确定中文不支持或具体触发原因。
- 后续计划最多 6 次串行、间隔 20 秒、固定 UA、不主动切换代理；首个英文查询即返回 HTTP 202 验证页，耗时 0.58 秒，立即停止。
- 本轮无成功结果，连续稳定性测试未完成；目前不能标记稳定可用。使用 Python requests，生产 Go 传输尚未测试。
- 本地诊断脚本与日志：`build/qa/ddg-stability.py`、`build/qa/ddg-stability.jsonl`。

- 分离搜索发现与页面正文获取；搜索摘要仅用于发现线索，不自动视为已核验原文。
- 配置提供商、端点、API Key、可用功能和预算；密钥进入现有凭据保护体系，不进入模型上下文、日志或导出。
- 核实 Firecrawl 官方搜索/抓取接口、认证、计费与内容使用约束，不假定免费或接口长期不变。
- 工具结果统一保存 URL、题名、来源类型、获取时间、实际抓取状态及内容快照；DOI/PMID 等存在时用于文献归并。
- 优先发现出版社、官方指南、注册平台和机构资料；普通网页不能不加区别地提升为论文级证据。
- 开放搜索不能直接解除现有下载域名限制。网页获取需设计 SSRF 防护、重定向逐跳验证、内网地址限制、响应类型/大小限制和凭据隔离。
- 网页、PDF 和搜索结果一律作为不可信资料，不执行其中要求调用工具、泄露数据或更改任务的指令。
- 发往外部搜索服务的查询不得默认包含上传数据、个人信息或未公开研究全文；必要时脱敏或请求明确授权。

### C. 科研数据对象连接器

UniProt、PDB、ChEMBL、PubChem、GEO、Ensembl 属于专业科研数据接入方向，不能简单当作文献搜索源混入候选池。

- 与文献源分开建模，保存对象标识、数据库版本、查询参数、许可、下载及解析来源。
- 依据目标用户选择一个完整场景试点，再扩展：数据获取 → 结构预检 → 分析 → 查看 → 复现导出。
- 不以新增连接器替代专业文件解析、环境准备和方法验证。

## 4. 新证据到报告更新的闭环

建议链路：发现线索 → 获取并保存材料 → 解析和索引 → 签发可定位引用 → 更新证据判断 → 标记受影响输出过期 → 重跑必要阶段 → 审查 → 新版本交付。

- 原材料、旧索引、旧引用和旧报告保持不可变，新内容产生新版本，不覆盖历史证据。
- 摘要升级全文后重新判断相关性与支持范围，不沿用摘要判定冒充全文结论。
- 根据实际依赖判定哪些证据综合、方法、解释、报告和审查需要更新，不能让旧审查批准新正文。
- 同一任务内按 URL/标识和内容哈希复用材料，保留来源；重复获取不反复签发等价版本。
- 获取失败保留原材料及限制；取消和重启可恢复，不重复已完成副作用。
- 已登记产物保持冻结；其后续修订需明确的新版本机制，不默认开放当前登记前返修入口。

## 5. 有边界的自主调整

常规检索仍保持当前首页策略，不恢复自动无限翻页，也不按“简短综述”随意降低质量要求。

- 正式补证记录具体证据缺口；此要求不适用于普通联网查知识、数据入口或软件用法，不限制 AI 按需使用通用工具。
- 明确请求数、候选增量、正文获取数、时长及费用预算；出现重复无增益、来源持续故障或预算耗尽时停止并说明。
- 技术重试和已授权范围内的定向补证可自动执行，用户无需操作“扩大检索”按钮。
- 核心方法、研究对象、结论目标、敏感数据外传或额外付费授权发生变化时，需确认。
- 不能为了补证悄悄扩大人群或更换课题，也不能把检索未命中表述为不存在相关研究。
- 对新增补证材料采用明确的筛选与纳入记录；自动补证不绕过现有选材确认边界，是否自动纳入须在授权策略中明确。

## 6. 科研正确性与流程分级

- 对用户未知而文件无法证明的配对关系、实验单位、重复测量、单位和研究目标按需确认，不强制固定字段模板。
- 对常见统计任务增加独立数值验算，覆盖样本量、缺失处理、效应量、区间、标准差/标准误，以及正文/表格/图形一致性。
- 文献综合明确观察与干预、相关与因果、摘要与全文、论文与独立研究；追踪冲突证据和未采用原因。
- 引用校验除来源完整性外，增加关键主张与原文支持关系的检查，不宣称自动语义检查能保证科学正确。
- 区分研究方案、范围受限综述、数据分析和专业研究；系统综述/Meta 分析需专门能力与验收，不能仅改报告名称。
- 简单任务减少无效中间处理，但不取消必要验证；复杂任务按实际风险增加检查，而非统一堆阶段。

## 7. 建议实施顺序与验收

所有条目当前均为待实施/待专项核实，不应整体标记完成。

### P0：先闭合现有证据链

下一轮先交付一个窄闭环，不同时铺开连接器：
1. 核对全文核验工具、材料保存、知识索引、引用签发的当前执行路径，固定一个“摘要不足、全文含关键结果”的测试夹具。
2. 补全文后生成材料版本并重新索引，引用绑定新版本；按内容哈希幂等，失败不覆盖旧材料。
3. 将新证据版本绑定综合/报告/审查依赖，只将受影响结果标记过期，保留历史冻结版本。
4. 验证断流、取消、重启、重复请求和全文获取失败，再用真实模型跑一次完整案例。
通用联网搜索已具备第一版能力，P1 下一步是搜索到网页读取及引用衔接的验证，不重复开发设置入口；专业连接器排在此闭环之后。

实现已有材料补全文后的持久保存、重新索引、引用再签发、依赖失效和重新审查。不以接新 API 作为前置条件。

验收：摘要不足 → 全文补得关键结果 → 新引用可定位 → 报告修订 → 新审查 → 新版本；旧版引用仍可打开。获取失败、取消、重启、重复调用均不损坏已有产物。

### P1：引入可配置联网搜索

设计统一搜索/获取结果契约和提供商配置，完成一个真实提供商端到端接入，优先评估 Firecrawl。同时完善现有文献源认证与限流状态。

验收：针对明确缺口发现官方材料 → 安全获取 → 接入 P0 证据链；无 Key、Key 无效、429、超时、预算耗尽、恶意重定向、资料提示注入均有确定行为，日志无密钥。

### P2：局部补证与科研验证
