# 系统架构与当前决策

更新：2026-10-31（提交分流、身份预检与开发调试边界），适用当前开发工作树。本文收敛旧 P0–P7 ADR 中仍有效的决定，不再以历史阶段编号定义当前能力。实现和验收状态分别见 [科研模式开发](RESEARCH_DEVELOPMENT.md)、[开发进度](PROGRESS.md)。

## 1. 一条应用执行链，不建第二套科研系统

```text
React：普通消息 / 问题卡 / 路线 / 阶段 / 报告 / 返修
  ↓ Wails Facade（DTO、事件、快照）
Application：Conversation + Chat + ResearchTask + Workflow
  ├─ 普通讨论 → Agent Loop
  └─ 已确认路线 → Workflow Runtime → Workflow AI Bridge → Agent Loop
       ↓ Tool Registry → 参数校验 → Policy / Approval → Executor
       ↓ Model / MCP / 本地工具 / Python / 文献连接器
SQLite + 项目私有文件：消息、执行、证据、产物与历史
```

- Wails 只在装配和传输边界；应用用例不依赖 WebView，便于临时数据库及受控模型测试。
- 开发专用 `scripts/research-debug` 在独立数据根装配同一 Application，经固定 HTTP 白名单调用原 Facade；桌面启动不导入或监听该接口，不另建科研状态机。每次模型 HTTP 外发前做持久预算准入，协商/重试/重定向也计数。调试使用方式与安全边界见[开发指南](development.md#科研流程调试入口)。
- 科研路线是一次确认工作的执行计划，不是会话本身。讨论、路线和产物复用同一聊天时间线。
- 不恢复废弃工作台或平行 task/job 执行器。数据库中为历史迁移保留的结构，不等于当前活跃产品入口；不能仅因代码名字老就删除持久化兼容结构。
- Workflow 当前以确定顺序串行执行；动态图不等于任意工具执行、节点并行或通用多 Agent 平台。

**代码入口**：[App.tsx](../frontend/src/App.tsx)、[Wails Workflow Facade](../internal/transport/wails/workflow_facade.go)、[Runtime](../internal/app/workflow/runtime.go)、[AI Bridge](../internal/app/workflowai/bridge.go)、[Agent Loop](../internal/app/agent/loop.go)。

### 研究状态的三种身份

文献综合的提交纠错不是新的研究路线：在格式与来源库存可验证之后，独立的 `evidenceGaps` 核读范围问题与引文问题集中诊断。`EvidenceSubmissionErrors` 保留两条错误链，聊天域引用映射只转换诊断副本，不改变冻结证据。混合修正沿已有 `submit_stage_repair` 入口，以本次拒绝稿哈希绑定原文选段与可选作用域（仅显式替换 `evidenceGaps` / `coverage`）；该作用域只在当前诊断确有范围问题且冻结 Schema 声明这些字段时签发。合并完整结果再次进入同一宿主验证、持久化与独立审查。没有自动认定证据缺项已完成，没有增加修正次数或新建用户确认按钮。

原生提交保留模型明确选择的控制身份：`submit_stage_repair` 的参数先按当前控制器的补丁 Schema 校验，错误保留原基线和诊断；`submit_stage_result` 只走完整稿校验，不跨接口套用局部合并。兼容的无原生名称文本仍沿原解析规则，不猜测所有文本都是补丁。独立审查的稀疏进展身份由实际 issue 合并成功回执提供，不再另行解析原文，合法裸 JSON/单 JSON 代码块与原生补丁一致；回执不是科学接受，仍要求原机械缺陷严格缩小，且只使用既有最多一次额外修正。原文先完整审计，完整合并稿再进入当前宿主校验，坏补丁、完整重交和未知/科学错误不借此增加预算。

- **需求与时间**：新规划分别冻结用户原话、宿主日期/相对发表年份解释及已确认问答，沿路线进入阶段输入；它们不是文献证据，也不能覆盖后续用户变更。原话只来自真实用户消息，AI 整理与内部工作流消息不能成为新增承诺。
- **发表时间解析与依据**：宿主冻结与检索提交校验共用 `resolvePublicationTime`，保守识别明确双端年份、近N年、起始年至今/以来及对应已覆盖的英文表达。派生终点只取已冻结日期，不取重试时当前日期；原文选择仍逐字校验，不能要求原话包含宿主推导出的年份，也不能补写引文或用0取消已识别的范围。新规划保存解析结果，明确的后续发表范围可替换旧锚，无关年龄/随访/实验日期不覆盖它；含糊或冲突表达不猜测。旧输入不迁移：已有冻结日期且原样要求可解析时可按同一规则核验；没有日期的旧相对时间元数据只保留原兼容契约，不补造新日期或升级权限。
- **逐文档分析与综合**：宿主检查点保存各文档科学输入指纹，不以综合返修代数清空全部工作。完整宿主校验并保存后，分组完成、最终综合及请求本地补查的原事务事件都可登记执行身份/指纹；复用仍要求成功输出哈希、运行/阶段归属及版本匹配，不继承科学批准。新 `document-analysis-v2` 只在私有哈希投影中排除 `documentCoverage.queries` 的纯字符串数组，检索审计仍完整进入模型输入；引用、文档/索引、覆盖数量/状态、读取范围及未知形状都保留，科学目标与用户变更仍失效。v1 检查点按原查询敏感算法匹配，未版本化的旧检查点仍按原 sourceKey，不重标或猜补历史。覆盖综合可显式替换少量完整记录，先校验库存/引用再合并，下游复用合并工作；旧冻结输入、原输出和审查门禁保持。
- **保存原稿与阅读视图**：`ResearchReportLayers` 只派生简版、正文、已知程序附录的显示切片，按需挂载到既有阅读器；不参与科学批准、保存、登记、导出或报告哈希。不同研究方向不必输出固定简版结构，当前卡片与历史共用展示逻辑。

## 2. 事实源与数据对象

| 对象 | 职责与边界 |
| --- | --- |
| Project / Workspace | 项目归属和本地文件边界，不自动授权所有任务互读 |
| Conversation / Message / Chat Run | 人类讨论、模型请求、工具循环、用量和终态 |
| ResearchTask | 同一研究的讨论、规划、执行和返修历史归属 |
| Workflow definition / compilation / run / step | 定义版本、编译后的工具契约、冻结输入、步骤结果和尝试 |
| Workflow AI execution | 将阶段身份、提示、Schema、模型和工具范围绑定到 Chat Run |
| Attachment / Knowledge Document | 已保存附件与显式知识库成员是两件事 |
| Citation / bibliography / evidence | 冻结证据身份、原文快照、书目信息及研究判断，不可互相冒充 |
| ArtifactVersion / Export | 不可变产物版本与独立派生导出；不覆盖原始研究结果 |

SQLite 使用纯 Go 驱动、迁移校验和、外键和事务；项目索引和大对象留在项目私有目录，不把全文都塞入全局库。全局事实与文件发布不是一个跨文件系统事务，靠暂存、内容寻址、原子发布及恢复协调，不能承诺任意断电都没有孤立文件。

关键状态先持久化再发布版本化事件。事件可能重复、漏收或乱序，UI 通过快照和 revision 校准，不依靠动画或前端状态宣告完成。审批、人工选择、取消与迟到响应都必须匹配当前执行身份；应用重启不自动重放有副作用操作。

日志使用标准库 `slog`、JSONL、统一脱敏与有限轮转，不以原始 HTTP/工具输出替代公开错误。数据根下的全局库和项目私有对象共同构成持久事实；移除外部项目不应删除外部 Workspace，托管项目按可恢复回收策略处理，缓存清理不能删原件或产物。

桌面主进程另存有界 `desktop.jsonl` 和 `desktop-session.json`，记录启动、关闭入口、关闭完成及原生错误调用位置；Go 未处理 panic 写入 `go-crash.log`，不吞掉异常假装成功。GUI 控制台句柄失效不能阻断文件日志。运行时 IPC 正文不进入桌面日志；原始 panic 栈仅作本地诊断。重开遇到上次未完成标记只说明“未记录正常退出”，不能据此推断 OOM、闪退位置或进程死亡时间。

关闭时先停止 Workflow 驱动、以宿主原因中断活动 Chat，再退出执行资源；`APP_CLOSING / interrupted` 与用户取消分开保存，已完成结果和已提交问题卡保留。重开不自动调用模型；AI 阶段仍由原卡片“恢复当前阶段”显式重试，工具副作用边界不变，不回写旧取消记录。

科研运行删除在单事务内校验范围、所有相关 run 终态和活动对话，仅按任务查询，不调用完整详情装配。`run_events` 是无外键的多态表，由 run/workflow 删除触发器按类型清理，并保留其他事件类型的序号；11 个子表索引减少级联扫描。启动维护有界扫描既有孤立事件与对应序号，每批 1000 行、批间让出连接，关闭先取消维护再关库。仅删除父运行已不存在的已知类型事件，不删除现存任务或产物；完成标记避免每次启动重扫，不执行 VACUUM。删除各事务阶段记录耗时，不记录研究正文。

**代码入口**：[SQLite](../internal/storage/sqlite/)、[events](../internal/events/)、[workflow repository](../internal/storage/sqlite/workflow_runtime_repository.go)、[view update](../internal/transport/wails/view_update.go)。

## 3. 三种模型协议与恢复分层

### 共用执行协议（2026-10-19）

- `internal/app/reviewcontract` 是独立审查—门禁交换的唯一核心投影、完整结果视图、JSON 身份比较及门禁判定实现；`reportview` 负责精确还原正文与程序附录。原始输入按保存字节计算 SHA-256，语义比较保留 JSON 数字精度；两者不能互相代替。
- Workflow 的 `currentReviewOutput` 供门禁执行、被拒审查的返修建议、最终交付登记共用：同一依赖、当前尝试、已完成 AI 输出和冻结契约。没有第二套宽松发布/登记路径，completed 标志不等于科学批准。发布还会逐引用复核来源。
- 模型提交的 `reviewedInputSha256` 可省略，由当前执行的冻结输入确定性绑定；归一化函数返回转换元数据，原始模型文本与最终规范化输出分别保留。预提交检查只读，不保证每次另有独立归一化事件。若明确提交其他摘要则拒绝，不能借省略字段跨会话/任务/阶段提交。approved、科学发现和修正建议仍由模型提供。
- `RunDetail.recovery` 是只读恢复投影，携带阶段 ID、尝试、动作类型、用户可见范围及是否调用模型/需要副作用确认。前端展示与后端 Retry 用同一规则；null 明确表示无可用动作，点击后重新核对实时状态。它不是权限令牌、持久化新任务或自动重试机制。
- 普通阶段重试和上游返修的持久化重置要求 `RetryGuard`：先捕获读取前的事件序号，在同一 SQLite 重置事务内比对已检查的运行/阶段身份、状态、尝试、冻结摘要、取消/恢复标志及该序号，上游返修另绑定生产者身份和尝试。不能从后读到的事件列表推导新序号，否则旧状态与新事件混读仍会误接受取消 ABA；读取期间的新事件只会使栅栏过期。冲突在决策、历史或材料变更前返回 `WORKFLOW_RETRY_CONFLICT`，不启动新模型请求。内部读取序号不进 JSON，也不是全详情一致快照、UI 授权令牌或所有工作流操作的通用锁；幂等工具重启恢复共用该原子重置契约。
- 新设计审查的 `revisionWriteContract` 只在新 Schema 支持 `editTargets` 且真实报告输入/依赖边一致时绑定。宿主以源阶段、尝试、完整输出摘要及 pointer 签发阶段结果、设计材料集合/单项和报告自撰正文等对象；计划显式选择 ID，起点必须是所选对象的最早实际 owner，不把依据引文等同编辑范围、不按关键词改起点。返修事件保留原契约、摘要和宿主版本，消费前核验；组合计划按对象 owner 分发各阶段清单。未知/过期/重复 ID、收据损坏或 owner 不符均拒绝，原计划和科学否决不改。结构一致不证明模型选对语义对象；旧图/历史不升级，缺绑定的历史材料建议不猜自动起点，保留显式手动选择。
- 对话返修 `revision.propose` v8 使用真实报告与图边派生的写对象；`task.read` v9 的只读 overview 提供当前对象、能力、版本/摘要和任务快照导航，原读取定义及权限不扩张。提案保存原 `editTargets`、完整对象契约和字节摘要，列表、完整详情及时间线共用安全投影；受保护材料路线的旧缺绑定/过期卡只读可回看、不能确认，须在同一任务重提，不能原地升级。确认事务同时核对不可变提案、真实重置起点及原输出/比较基线，数字比较保留字面精度；下游 `_userRevision` 携带原声明与全部协商要求。合法材料/数据/源码版本选择继续各自原显式授权契约，与非空 `editTargets` 混用须拆案；此分离不能证明自由文本没有要求其他修改。旧 v6/v7 在途提案调用按原 fingerprint 明确拒绝，不静默升级；旧已确认提案及结果不追改。
- v8 新设计 owner 授权另绑定 `design-material-isolation-v1`。从不可变已确认提案及原事件双锚，读取确认事务保存的完整前快照；校验同 Run/编译、阶段身份、旧尝试及完整 output 摘要，不把截断预览、失败候选或模型可见 `_userRevision` 当原稿。实际提交仅可改所选材料的 `markdown`，所选集合只可尾部新增；其他设计字段、材料标题、旧项顺序保持原值。明确选择 owner 的 `stage_result /analysis` 才授权整个设计输出，确认卡显著说明该宽范围。仅对当前实际选中的材料 owner 隔离，不把未选下游重建或宿主报告附录误判为材料写入。字符串逐值比较、数组保序、JSON 数字不转浮点；重复字段（含转义同名）拒绝，候选原文不拼回、不清洗。预提交、最终执行/恢复和人工采纳在相同已验证引文还原域核对；越权进入原两次纠正，坏历史绑定直接停止，不消耗格式纠正、不自动再修。
- 后续显式审查返修使用新的小型写隔离回执替换旧授权：采用建议保留原 `editTargets`，手动明确阶段起点才授权其后缀完整重建；合法的上游/报告选择也保留版本化回执，不能与缺记录混淆。完整原稿只放 `workflow_revision_write_snapshots` 私有不可变表（迁移 104），在原重置事务内用最新 Run/Steps、真实 producer 输出和原 review/门禁核验后保存；事件、时间线和模型仅携版本、摘要与对象 ID，读取再次核摘要并按 Run+事件限定，任务删除级联清理。普通重试/自动实现修复不扩大范围；旧冻结审查缺有效新范围且会触及当前窄材料授权时，在重跑前明确要求同任务重提，不先付费跑上游再中断。对象写隔离不是自然语言意图或科学正确性证明：所选正文内的语义、未选下游的科学一致性仍须原独立审查与内容验收。
- 新审查材料 owner 的阶段输入从同一私有原稿投影实际已采纳的 `Step.Output.analysis`，不以同 attempt 的旧 AI 输出代替人工采纳结果；仅投影所需 owner 原稿和摘要，不带整个私有快照，也不把事件 ID 冒作旧 proposal 分页权限。后续确认的回执在提示与实际校验两端均优先于旧用户范围。手动前移起点未被原审查计划命中时，只补真实授权/原稿上下文、保留空本地纠正项，不制造发现；坏上下文仍停止。私有新快照存在但回执丢失时明确失败，不降级旧流程。项目归档重映射外层 Run/事件关联，保留原稿字节及摘要作为历史证据，不自动将旧身份原稿变为恢复后的执行授权。
- 初次构建阶段视图时，软压缩阈值若容不下固定规则导致分页无解，可在不改变实际窗口和读取权限的前提下重新计算一次本地分页预算。同一执行的后续纠错继续原阅读视图，不能靠重新分页抹去已读材料。
- 入选文献汇总的存储准入与模型准入分离：已授权任务读取的 coverage 输入按现有快照字符容量核验并完整保存，不用 220 KiB JSON 字节数冒充模型窗口。摘录、普通分析、历史返修与长工作统一进入后续通用阶段投影和实际请求预算；未授权读取的阶段不新增权限，超出持久化容量仍明确停止。
- 新路线通过冻结节点的 `stageMaterialsVersion: source-v1` 启用阶段原文交接，旧节点缺省不启用、不追改。宿主核对当前任务、阶段、尝试、Chat Run 和输入摘要，只选本轮已完成前序阶段的成功完整读取：当前仍允许且前后包身份相同的 Skill 章节，或与当前冻结输入/绑定的真实工具产物哈希相同的完整 UTF-8 文件快照。仅复制原文与来源身份，不复制旧模型会话、审查结果对象、旧资源 actionId 或已读标记；原产物文本可能含模型撰写的主张，仍作为不可信资料而非已批准事实。当前阶段仍实际加载并验证原 Skill 快照。
- 原文交接最多 24 条、单条 12,000 字节、正文合计 48,000 字节，原请求和证据先通过原预算，再加入完整可容纳条目；没有来源或历史可选读取不可用时不宣称已有材料，原读取入口仍在。实际发送子集及顺序仅以指纹随成功用量观察保存，恢复时只能在当前已验证来源集合中重建，优先原样匹配而不把每个前缀当新内容。真实计费、完整实测池和原安全余量不扣减：交接仍占上下文，不能承诺所有后续请求比无交接零额外成本，也不强行塞满窗口。缓存快照不证明可变路径现在仍有相同字节，独立审查仍须针对疑点核验。
- 新编译数据路线用完整版本 token `p` 区分交付职责；实现 v7 保留 v5/v6 的提交兼容。模型仍负责算法、数据语义和已承诺的质量检查，不靠行数/篇幅硬截断减重；Kernel 的代码、环境、参数和文件摘要由程序生成计算执行记录，不让模型重抄。记录只绑定本轮已完成 Python 阶段、精确源码/输入集合/参数摘要和完整产物；参数摘要复用 Kernel 的数字保真规范化，不能验证则明确拒绝，记录存在不代表科学正确。
- 计算记录沿原报告组装、附录拆分/原样还原、独立审查及门禁链保存。新策略只在原 JSON 解析器选定候选时投影掉连续、完整、完全相同的当前计算附录；其余原始 JSON 字节及正文继续原 256 KiB 候选和原 Schema 限制，再恢复单份记录，去重仍记前后摘要。未通过候选不提交投影状态，原围栏/格式修复语法不另造宽松入口。仅附录、篡改记录或另有同名冲突记录均拒绝；历史冻结输入/正文/摘要不追改。
- 新编译且确有设计阶段的报告用完整版本 token `dm2` 冻结材料组装策略，旧 queued 图不因当前程序升级而改变。宿主确定性承接全部非空 `deliverables` 到独立报告附录视图，不按偶然相同子串跳过材料；模型负责自撰正文，不能通过报告替换上游材料。精确绑定的完整宿主附录沿原计算记录解析投影和还原链，不占原自撰字数/字节预算；错误尾段、篡改/冲突同名附录没有此例外，原文本和转换审计留存。设计材料独有的可信引用也进入书目，重放不从旧宿主记录伪造新引用或重复追加。

恢复分开处理，不能把所有错误都叫“重试五次”：

- **三协议模型单次传输（2026-11-06）**：Chat / Responses / Anthropic 的聊天与科研客户端从构造起使用标准 TLS + HTTP/1.1 新连接，禁用连接复用及 HTTP2 下层透明重放，不在失败后换路；模型 JSON、凭据、模块代理、重定向、错误分类和宿主重试预算不变。HTTP 301/302/303 的 GET 与 307/308 的 POST 均再次准入；计数是预记尝试，连接失败可偏多，不是账单或 token 限额。TCP→代理握手→TLS 的连接建立期独立限时，原请求取消会关闭尚未交付的连接；GotConn 后清除建立期限，响应头沿原独立等待，健康 SSE 无整段总超时。生命周期仅作用于不复用的单次路径，不给网页浏览器共享拨号挂上原请求 owner，避免原请求结束误伤其他使用者。Gate 转发 CloseIdleConnections，清理不打断活跃建立或正文。浏览器指纹 IPv6 仅规范主机身份，不跳过证书核验。网页 / Embedding 仍沿原浏览器路径，依赖 H2 补拨与代理握手的存量边界不据此宣称已修；新 HTTP/1.1 路径未作真实模型验收，结果只见[开发进度](PROGRESS.md#模型-http-四项缺陷修复2026-11-06)。
- **传输错误**：请求建立、流读取各有最多 5 次重试；只接受可重试分类，共享同轮恢复等待预算（默认 12 分钟）。失败请求/生成耗时计入预算，健康持续输出没有整个任务的固定总时长上限。
- **请求启动诊断**：模型 HTTP 传输失败的私有错误携带宿主 `httptrace` 里程碑与请求字节数、相对计时，恢复审计写 `source=host_network`，不把本地解释伪装成坏服务 JSON；阶段不能由上游文本自报。写入回调不保证最终 Flush 或服务端收到，故无首字节时保守标为 `request_flush_or_response_headers`；连接获取次数不是 TCP 拨号次数，并发拨号迟到失败不撤销成功。代理/多层 TLS、跨多次获取的迟到回调不能精确归因；调用方取消/deadline 仍沿原适配器返回，不保证携带 trace，实际 HTTP 错误继续以原类型化状态为证。新增结构化诊断不含地址、请求头/正文或原始错误文本；TLS 公开详情不再复制 URL，但为兼容保留原 Cause 链，不宣称全应用原始 `Error()` 均无 URL。仅诊断增强，不更改代理、超时、SSE、重试次数/预算或科学校验。
- **SSE 协议错误**：显式空行闭合事件与未闭合即 EOF 分开。仅后者的 JSON 未结束属于可恢复截断；闭合残缺 JSON、中段语法和协议类型/结构错误停止，不自动补全或重复请求。合法 JSON 缺末尾空行仍兼容。真实故障另确认服务把正常增量/完成推理项和完整 error 缺分隔符粘在一起；分帧器只额外保留每个实际 data 对应的显式通道及转换位置，标准 Text 分帧不变。仅真实转换到 error、恰好两个合法 UTF-8 单行对象、匹配前通道的已知增量或严格完成推理项＋扁平错误时只读取终止失败，不发出前缀/原生状态/工具或草稿。字段类型、重复键/别名、已有 refusal、消息/工具前缀及未知结构仍拒绝；这一分支仅三个精确传输身份沿原预算恢复，认证/配额/未知码不因子串或消息扩大重试。它不是通用 JSON/内容修补，不能修复服务端断流或写帧。新流错误与 HTTP 200 解码错误仅保留字节数/指纹、允许的类型和位置等元数据；任意上游消息和原生内容不直出。恢复审计重新投影并从类型化错误保留真实 HTTP 状态，不能从不可信标签造状态；旧诊断不追溯清洗。
- **停滞流**：有效进展看门狗，不让 SSE ping 伪装生成进度；默认空闲基线 5 分钟，另受连接配置及剩余恢复预算约束。
- **模型服务内容检查拒绝**：明确的 policy `invalid_prompt` / `content_policy_violation` 映射为 `MODEL_PROMPT_REJECTED`，非可重试；保留服务诊断，不自动改提示或换服务，不推断用户题目违规，未知触发位置如实披露。用量统计按请求拒绝 400 分流，不记成内部 500。
- **服务错误伪装成成功文本**：仅已证的独立 `[error: …]` 配额标记与 `no_userid` 在终止边界转成服务失败，不作为科研提交、正常回答或上下文摘要，不消耗格式纠正；保留原始文本指纹，摘要仅在通过该检查后沿原成功规则 trim。正文、引用、JSON 字段和未知标记不猜测分类。SSE 已解析的 `no_userid` 身份不因限流包装重试；HTTP 只识别无重复/大小写别名冲突的顶层 `error.code == no_userid`，在状态重试及三协议参数/缓存协商前停止，不修改能力缓存，不猜填用户 ID。HTTP 状态与原 body 指纹保留，公开诊断只含安全元数据；不是对所有服务标记或原生 SSE 重复键解析的通用修复。
- **文献候选身份错误**：冻结批次的未知/重复/缺失 ID 一次诊断；可局部处理时以原候选哈希约束 `candidateIdentityPatch`，只修诊断中的 ID 字段，模型显式选来源；合并后完整校验，不猜 UUID、不改科研判断。提交失败另外发出脱敏、有界诊断事件，原候选审计不变。
- **模型工具名/参数错误**：保存不可执行的失败 ToolResult，回给模型纠正，不把拼错名称当程序崩溃，不执行猜测的替代操作。
- **科研输出格式/内容错误**：同一上下文最多两次修正，已保存的原提交与诊断保留；不是网络重试，也不自动重跑整个阶段。
- **科学审查不通过**：保存合法的拒绝结果和具体发现，走返修而不是当 API 故障无限重试。
- **阶段恢复展示**：后端可选 `failureKind=model_protocol` 仅区分展示，不改变 Retry 权限。原卡指明重试阶段、仍有效成果和实现分件可复用，网络 SSE 不续传，成功后按路线继续且可能再次产生模型/审查费用。正式失败任务和重启不会自行恢复。
- **审查依据定位**：完整条文在当前冻结 `acceptanceCriteria` 内唯一逐字匹配时，可审计恢复错误数组下标；科学来源不做全局搜句替换。路径、状态说明及能独立判断的对应关系同轮反馈，避免先修一项、下一轮才暴露另一项；Schema 失败时摘录匹配仍等引用身份恢复后验证。仅已明确诊断的路径/摘录/状态说明可作同 run、SHA256 绑定的局部替换，不重写正确单元；混合实质问题回到完整提交。原补丁先入不可变审计，合并结果再走完整冻结检查，不补科学或授权字段、不改判定、不增加两次修正预算；新执行标记 `review-repair-v1`。
- **结果未知的执行**：按幂等性和副作用语义恢复；不能拿模型连接恢复机制重复计算或执行命令。

### 提交接口与明确拒绝

- 新动态独立审查执行采用 execution-only `|review-source-v2`：首次 `submit_stage_result` 的完整审查及后续 issue replacement 的 basis 只接收当前来源片段 ID 和可选的成对 Unicode 偏移，不再接收模型手写的 pointer/quote。宿主从当前冻结输入的原白名单标量复制；判断、历史 ID、理由、修正及返修目标仍归模型，复制后继续原完整格式、引用、历史、科学检查和门禁。旧冻结 `review-source-v1` 执行保留原指令和扁平目录，不热升级；符合原重试与快照检查的技术失败，可显式重试当前审查，由新 attempt 生成 v2，不重跑已完成上游。此执行级修复不要求重新规划或重传材料，与文献综合的冻结 Schema 版本条件分开；不能从材料中的文字启用协议，不扩大权限。
- 来源目录是完整导航而非正文副本：同一执行共用 ID 前缀，逐字段列片段边界及原 JSON 坐标，区分需求与数值/布尔整值。v2 在节省空间时用 `prefix-groups-v1`：每组完整路径前缀与本组行后缀直接拼接，不再解码或跨组引用；所有标量、顺序、全局片段位置和坐标保留。原 JSON 坐标按原序列化单次索引，分组搜索有界且可取消；v2 对可选来源沿用 reader 的单路径 2048 Unicode 字符上限，并将来源路径总字节限为 16 MiB，超限明确停止，不静默省略，旧 v1 不追加限制。首次材料视图构建与最终提交共同计入完整目录和版本指令，沿用原窗口、证据分页及失败即停，不挤掉已准入证据。pointer 读取只用实际开放的 Schema；旧 reader 的全 JSON 坐标与解码后单值偏移严格分开。目录/共享路径中的合法工具名是数据，不能在 provider 名称投影时改写；独特材料或固定规则确实超窗仍会拒绝。
- 选段须完整存在于该次实际请求可核验的原输入视图、单跳相同共享值、实际工具页或已保留片段中；已取回但隐藏、仅目录、旧尝试和已不在上下文的阅读记录不算。JSON 父页与旧全 JSON 页按原位置、完整转义 token/代理对映为后代标量范围。提交和协议滚动包装保留不可由模型设置的工具身份与前缀，再校验当前实际内容，不从正文猜来源。可见性只证明原文暴露，不证明论断成立或全文阅读完成。
- 原始选择参数先进入不可变 journal，只有派生依据转换至当前已验证 Chat 引用域；冻结原文、目录坐标和旧历史不改写。普通字段错误、来源定位错误与科学否决分开；来源在当前提交中不可安全证明可见时明确停止，不在提交锁定后要求不可用的 reader。完整空响应/缺原生动作先审计再停止，不额外付费重发；其他可修正提交仍共用原两次预算。

- 新动态路线的文献综合以冻结输出 Schema 的 `title: citation-source-v2` 显式启用首次选段和失败后的字段修正；执行身份追加 `|citation-source-v2`。既有 `citation-source-v1` 只保留原首次选段接口，不获得字段修正；无标记的旧 `selected-evidence-v6` 路线、旧 Schema 和已保存执行均不热升级。只在完整结果包含 `citationAssessments` 时启用，逐文档 `batch` 仍按原独立契约。新首投与完整重交用必选原生动作，`quoteSelection` 只替代模型手抄的 `supportingQuote`；科学判定、推荐、理由、覆盖和文档分析不由程序补造。读工具后的续交也保持同一原生协议，不重新引入围栏文本终止指令。
- 文献选段目录只列当前 Chat 通过既有 citation resolver 核验的签发来源、原文哈希、连续片段 ID、Unicode 边界及 `lengthSafeEndId`，不复制原文或充当核读收据。冻结候选复用原值/分页的实际可见范围；本轮新签发工具块当前保守要求完整原文块实际可见，不以截短 preview 中一段相似文字放行。引用别名还原不能证明正文原字节可见：所选范围碰到被重写的旧 marker 时，须由不作别名还原的真实原文页或原始工具文本证明。未知 ID、跨来源、乱序/重复/跳段、未成对偏移、隐藏原文和原 700 字符上限仍拒绝；模型显式 exclude 才可给空选择。
- 原始选择参数先保存在不可变 journal，再复制明确选择的原文并执行原完整格式/来源/科学校验。新协议 `supportingQuote` 不再经过旧手抄摘录的首尾空白/字形纠正，引用字段仍正常从 Chat 还原到 Workflow 域；最终提交、恢复重放和下游 analysis 绑定均保留选中原文。来源中自带 marker 仍受原引用/科学检查约束，不为通过而换 marker。目录、选择 Schema 和契约开销参与首次视图预留与最终预算；放不下则调用前停止，不挤掉已准入证据、不扩大窗口、不追加纠错或网络重试。旧纠错控件继续只用其实际开放的载荷与预算。
- v2 在可解析的完整候选被拒后提供可选 `submit_stage_repair:{baseSHA256,resultUpdates}`：只替换模型显式给出的完整顶层字段，未给出的值保留；数组须完整替换，相关引用、判定和结论仍由模型一并修正。绑定、向模型展示与后续合并均用同一原生 `quoteSelection` 稿，不拿派生 `supportingQuote` 稿冒充基线；原稿和每份补丁先保存在不可变 journal。重复键（含嵌套）、过期基线、未知/混合字段及不合法字段值明确拒绝，不由宿主选择第一/最后值。无效补丁不替换基线。每次合并重新检查所有选段在当前实际请求中的可见性，并经过原完整格式/来源/科学校验；不裁剪、不自动改判、不增加原两次修正，完整重交仍可选。字段修正使用自身格式反馈，不混入 v1 引用补丁字段。窗口容不下控件则在调用前停止，不挤掉已准入证据。
- 字符串和集合大小的拒绝反馈包含实际值及原上限（字符串按解码后 Unicode 字符计），与已有有界多字段诊断共用原接受规则；提供精确修正依据，不保证模型能在预算内提交科学合格的整稿。

- 已确认原稿的局部编辑使用新阶段输入中的 `_revisionEdit / revision-edit-v1` 回执。宿主从当前已确认提案＋原事件双锚的完整快照，或当前审查续作私有快照读取实际 `Step.Output.analysis`；不以失败候选、旧 AI 草稿或模型自报原稿作基线。纯报告提案独立核对其确认快照，不伪造设计隔离版本；后续审查会阻断旧提案复活。已有冻结输入不热升级。
- 新控件 `submit_stage_edit` 只接收原稿哈希及明确的字符串叶子 `path / before / after`，路径必须以 `/` 开始并相对原稿 analysis 对象寻址；原文须唯一逐字匹配，每个字段至多一项。空编辑是模型显式选择复用完整作者稿及方法摘要等元数据，不代表科学批准。需要结构、结论或其他字段变化时，仍可明确选择原 `submit_stage_result`。指引要求只调用本轮实际开放的一个完成控件，不混批执行；不从自然语言自动猜替换、不静默修回越权全文。

- 新原生规划的冻结提示与当轮请求复用同一宿主传输契约，只在拼接前适配已认证的宿主片段，不改 stage_input、Skill 或历史原文；不再同时要求代码围栏/响应正文提交，问答字段明确嵌套在可省略的 clarification 内。完整终态缺必选调用（包括完整空响应）不是内容格式错误：先持久化原文及提供的完成项，拒绝优先，否则报 `WORKFLOW_AI_NATIVE_ACTION_MISSING`，不自动重发、不消耗两次内容修正、不补造调用。完成项或原文保存失败先停止；中断、截断、网关错误和过滤仍遵循原优先级。有真实调用但参数不符时继续原纠正及科学检查，不能借版本标记跳过验收。

- 格式诊断以原严格 Schema 校验的拒绝为前提，不改变接受规则或已有归一化；按稳定顺序收集至多 20 条独立字段，再保留原首要错误。新增诊断遍历/比较计同一 4096 工作量上限，长行有界、保留摘要与截断说明；有界诊断不是全部缺陷证明，也不是科学审查结果。

- 强制/必选工具与 Anthropic 扩展思考不兼容，单请求关闭思考且不污染能力探测；最终上下文预算与用量锚点包含该模式。
- 同一错误摘录在完整替换里重复时，仍经原完整校验，同时反馈未修正并指向连续原文 ID，不自动补空格、猜词或换来源；完整重交仍可修正科学判定，不能强制用不支持原结论的摘录。
- 原生 `refusal`（含 Responses 内容块、Chat 的流式/非流式 refusal 字段）与保守识别的非结构化开场拒绝，科研执行记录 `WORKFLOW_AI_MODEL_REFUSED`；空原生拒绝记录 `MODEL_OUTPUT_REFUSED`，不按空响应自动重连。文本最多跳过一个不超过 256 字符、独立的明确模型身份段，再检查明确拒绝；统一空白行边界，不跨段查找补证据，JSON、来源引用、一般说明与普通进度不因包含拒绝词而触发。纯身份介绍不等于拒绝，仍遵守原缺提交续交上限；自然语言覆盖有界，不保证所有拒绝都可识别。普通聊天仍可显示拒绝回答。
- 基础上下文、研究开场和讨论将 SciAide 描述为宿主应用，不要求模型改名/改变供应商身份与政策；Skill、冻结材料、权限与科学门禁仍按原职责。提示调整不等于响应方会执行工具协议，不据拒绝文本倒推出其内部路由或政策根因；明确拒绝后停止，不用重试、裁证据或自动换服务绕过。
- 用户显式重试以同阶段、同输入的最近一次执行为准；不能跨过较新的拒绝、网络错误、取消或成功执行，捡回更老的格式错误要求。拒绝后的新尝试明确为用户重试，不指示模型绕过服务政策，也不把旧草稿当最新研究结果。
- 拒绝先保存原文/协议记录再停止；代码分段保留已存前缀、不消耗一次格式纠正。最终格式耗尽或拒绝诊断保留此前尚未解决的具体问题；按钮仍为显式重试当前阶段，重启不自动重发，不改为科学返修，不换供应商绕过拒绝。

## 4. 上下文是有界投影，不是数据库删减

- 人类讨论与内部阶段 prompt 分离，继续追问不重复携带整条科研流水线。
- 模型窗口、有效请求预算、自动压缩软阈值区分处理；不能因为大阶段输入超过软阈值，就在没有可压历史时反复压缩。
- 使用实际输入用量观察校准估算；最终请求仍要把提交 Schema、纠错反馈、工具定义、用户回答和原生协议计入，而非只测首次 prompt。
- 阶段预算投影由 `ProjectResearchStagePrompt` 统一组合：以当前材料视图继续缩减，不从完整冻结输入重建已分页/共享的内容。已有 `$read`、`$same` 及其一跳完整字面目标和解释契约保持；新增分页仍定位原始输入的字段、字符边界与哈希，不定位投影视图。共享路径表无法核对时保留原视图，不猜测或丢弃引用关系。
- 只有总字节数和 Unicode 字符数均严格减少才采用新投影；存储层与 Agent 预算层共用此规则，不凭某个标记或“仍含 `$read`”推断安全。这不保证任意规模都能容纳，最终完整请求仍须通过原预算准入，失败时明确停止而非扩大窗口或删证据。
- 普通工具结果可以展示有界预览；原始结果仍保存并提供范围内的分页读取。用户回答、关键当前输入、Schema 和原生协议不能被当成普通预览随意裁掉。
- 工具 envelope 预算投影始终保留合法 JSON，显式标记内容/结构未展示；不把整页字节数或伪造的续页元数据保留成完整可见证明。源文件页按实际转义后的 envelope 大小缩页，再按真实读取字节签发同源续页，普通文本与 JSON 文件共用，不扩权限。预算允许时优先保留最新完整工作区页和当前任务页，其余为明确有损预览；包括旧损坏快照的多层预算投影也不改原结果、已存快照或原生审计。固定上下文放不下最小遗漏说明则明确停止，不返回空对象假装有可用资料。
- checkpoint 保存精确消息边界、revision 和摘要哈希；原文不删除。语义摘要有损，哈希不证明摘要完整。
- `source-sharing-v1` 仅把科研来源上下文中完全相同的 JSON 原值共享编码；不合并相似论文、不删除独特材料、不修改冻结输入与原始审计。
- 独特长资料仍可能超过窗口。现有机制减少无效重复，尚不是任意规模研究的完整按需材料系统。

本地斜杠命令由前端静态注册，精确匹配才执行，未知命令或带其他内容的输入仍是普通文本。`/mcp`、`/skill` 等是导航/选择入口，不授权工具；`/skill` 插入显式选择文本，不直接加载正文。`/compact` 只能在当前会话没有活动生成时执行，沿用同一 checkpoint 机制并以人类讨论为边界；可能调用模型并计费，不是纯本地无损压缩。

**代码入口**：[context_builder.go](../internal/app/agent/context_builder.go)、[request_budget.go](../internal/app/agent/request_budget.go)、[compaction.go](../internal/app/agent/compaction.go)、[research_input_sharing.go](../internal/app/workflow/research_input_sharing.go)。

## 5. 工具、资源、Skill 与 MCP 的职责

Tool Registry 是实际可执行能力的事实源；模型给名称和参数，不能声明风险、权限或幂等性。工具统一走 Schema、Policy、Executor、超时、取消及审计；科研执行还受冻结的阶段工具范围和任务资源归属约束。Full Access 不绕过这些范围。

资源接口把宿主已签发的文件、Skill、原文和任务结果操作展示给模型，分页、ID 和操作解析由宿主完成。目录是数据，不是授权；失效资源返回当前可用选项，不跨任务猜 ID。同一授权 run 的精确 step ID 可解析为 node ID。

动态 Skill：

- 来源优先级为 `project > user > installed > default`，正文按需加载，首次成功加载保存内容和包哈希快照。
- 默认 311 项来自派生 OpenScience 库；有界候选不等于全部能力，模型可继续发现，用户也可指定 Skill。
- 默认资源以 ZIP 嵌入，按读取解压，不启动时全量落盘；正文、资源、许可证与原哈希不因压缩裁剪。
- Skill 是方法资料，不是工具注册器。脚本先物化、核读，再通过原有 Shell/Python 工具授权执行；加载本身不执行脚本，不自动提供依赖或外部密钥。
- 依赖/外部服务/不可用状态是能力披露，不能把 Skill 数量宣传为可直接完成的科研方向数量。

MCP 按需发现、连接与执行边界见 [网络与扩展工具](NETWORK_BROWSER.md)，不维护第二份外部产品源码对照笔记。

**代码入口**：[tool](../internal/app/tool/)、[resource](../internal/app/resource/)、[opensciskill](../internal/opensciskill/)、[builtin tools](../internal/tools/builtin/)。

## 6. 材料、知识库、引用与产物

- 附件复制和解析是项目内原件保存；聊天上传不自动变为长期知识库成员。任务附件还需要发送和采用，选择文件不代表开始科研计算。
- 知识库使用本地 FTS5/BM25；可选 Embedding + RRF，服务失败降级词法检索。索引身份绑定配置与版本，影子构建成功后切换，不混写不同向量模型。
- 在线文献是候选；正式纳入、解析、索引和来源验证后才可进入可信证据链。摘要、全文、网页、题录分别披露，来源存在不证明支持主张。
- 正式引用绑定原文快照和来源身份；搜索与核读、同块不同摘录不能覆盖彼此。当前阶段只使用授权证据，不通过模糊匹配修复引用。
- 新报告的 `research-handoff-v1` 复用已保存筛选理由及精确引用到书目绑定，宿主生成来源附录，避免模型重复转抄。科学正文和结论仍由模型形成、独立审查。
- Artifact 版本、lineage 与引用快照不可变；DOCX/PDF 是绑定源版本和生成器的确定性派生导出，不等于覆盖原稿，也不是完整 CSL 实现。
- 项目归档包含明确枚举的项目关系与对象，不含密钥；隔离校验、ID 重映射后恢复为新项目，不原地覆盖源项目。

## 7. 计算与界面稳定性

项目 Python 环境与串行 Kernel 记录解释器、依赖、代码、输入、输出和复现哈希；环境变更、取消、超时或进程退出不能假装内存变量仍存在。长实现按完整片段保存，局部技术修复可对冻结源码应用精确补丁，完整检查及真正执行仍使用原管道。

Windows 进程边界使用扩展路径，元数据保留逻辑路径；建环境后用该环境的解释器显式运行原 bundled ensurepip，不改系统长路径设置、不用全局 pip。pip 的 wheel 文件 URL 往返会移除扩展前缀，故在同一 Python 进程先解析本应用缓存与原环境缓存的实际路径，再按 Windows 路径长度选定较短位置，随后经标准 runpy 进入 pip 模块；不改 pip 内部函数、不因错误换目录重试，相对应用根在构造时固定。两处都极深或第三方工具另有路径限制时仍可能失败，不保证任意深路径。激活使用已解析的实际根，仅去除 Windows 命名空间；核对完整 VIRTUAL_ENV 赋值与目录身份，不执行脚本或接受路径子串，不能安全写入 shell 模板的根明确拒绝。

Kernel 默认进程树内存预算不等于 OS 强沙箱；科学数据重算仍要符合已确认方法和材料。详见 [安全边界](threat-model.md)。

UI 使用分页时间线、离屏内容窗口化、revision 检查和有界视图缓存减少重复渲染；活动卡、焦点、选择和展开内容应保留。错误边界与原生 renderer 恢复不自动执行研究，不代表真实长期内存泄漏已经全部消除。

## 8. 何时重新评估这些决定

- 大规模独特材料超过上下文或索引性能目标：改进按需读取、版本化材料定位与检索，而非简单扩 prompt 或不断加重试。
- 新科研运行时、并行任务或远程计算：先定义能力、数据归属、资源与副作用，再接入统一执行链。
- 新协议或依赖升级：验证原生 turn、流恢复、取消与发布派生运行时，不只验证普通一句问答。
- 需要不可信代码隔离、跨平台发布、签名更新或协作：作为独立能力设计与验收，不能把现有 Windows 本地工具边界重新命名后宣称完成。
