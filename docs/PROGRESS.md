- **确定缺陷 2：HTTP2 下层重放漏计**。三种适配器通过 `bytes.NewReader` 构造 POST，默认有 `GetBody`；外层 Gate 只包一次底层 RoundTrip。受控 TLS + raw HTTP2 源站先对已收完整首份请求返回 `REFUSED_STREAM`，浏览器式 / 标准 `net/http` 均在同一 Gate 准入内发送第二份完整相同 body，实测 **Gate=1，源站请求流=2**。因此仅换标准传输不能兑现实际 HTTP 硬上限；需让真实重放进入预算 / 重试契约或禁止不可计数的模型 POST 重放，不能改个计数标签当修好。不据此声称已有案例双重计费或历史确切流数；上轮真实传输探针已设 `GetBody=nil`、每项只有一次写回调，保留原两次观测，不把新夹具追认成当轮发生过重放。
- **确定缺陷 3：Gate 丢失连接清理**。`gatedTransport` 只实现 RoundTrip，不转发 `CloseIdleConnections`；对包装后 client 调用清理不会到达原传输。同一可关闭 fixture transport 的清理计数为包装后 0、原 client 1，与代理取消后的遗留连接风险叠加。该问题同样不因底层换成标准 HTTP 自动消失。
- **确定缺陷 4：IPv6 字面量 HTTPS 失败**。当前模型配置允许绝对 IPv6 HTTP(S) URL。浏览器指纹依赖在直连路径对已去端口的主机再次按最后冒号截断，`::1` 变成 `:`，传给证书名校验。本机同一受信任证书 / `https://[::1]:port` 下，标准传输 200，浏览器式为证书名不匹配；仅影响 IPv6 字面量，不把域名解析到 IPv6 或本次域名案例混为一谈。
- **验证 / 证据**：七个相关包现有 **301 项测试通过**、七包 vet 通过。新增故障观测夹具均重现预期坏行为（不是修复通过、未跑 race）；独立复审结果经主审核对源码 / 日志。根目录 `.tmp/diagnostics/20261106-model-http-review/` 含 `before.json`、`transport_review_test.go`、`h2-replay-browser.json`、`h2-replay-standard.json`、`gate-close-observation.json`、`package-tests.jsonl`、`review.json`、`verification.json`；独立代理 / IPv6 的原夹具、overlay、日志及运行脚本在 `.tmp/diagnostics/20261106-transport-contract-review/`。主审夹具复跑先创建新的工作区诊断子目录并显式设置 `SCIAIDE_TRANSPORT_REVIEW_OUT`，仅运行保存的 `transport_review_test.go`；独立 overlay 脚本先复制至同层新证据目录再运行，避免覆盖原记录。
