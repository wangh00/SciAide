# ADR-0038：P7.4/P7.5 使用版本化 Workflow 与可恢复状态机

- 状态：Accepted
- 日期：2026-08-25

## 上下文

普通 Agent Loop 适合开放式对话，但长科研流程需要可预览的依赖、人工检查点、失败定位和应用重启恢复。让模型临时生成并直接执行任意 DAG 会放大类型错误、权限漂移、密钥注入和副作用重放风险。

## 决定

1. Workflow 是显式可选能力，不替代普通聊天。定义使用版本化 JSON Schema，包含输入输出 Port、Node、Edge、权限需求和节点副作用声明；保存产生不可变版本。
2. 编译器在创建 Run 前检查节点/边数量、循环、悬空引用、类型、路径、嵌套密钥、Tool 存在性和图体积，并冻结 Tool 名称、版本、输入/输出 Schema、风险、权限及幂等属性。无效定义不能运行。
3. 首批节点支持注册 Tool/MCP、Shell、项目 Python、人工确认、候选选择和 Citation 选择。Workflow 不能携带凭据、启用 Skill/MCP、选择任意解释器或绕过 ToolRegistry。
4. Runtime 当前按确定性顺序串行执行。每个 Tool 节点仍通过 ToolExecutor、PolicyEngine、Approval、项目解析和 Artifact 注册；不存在第二套执行或授权通道。
5. Run、Step、冻结输入、输出、ToolCall、审批和事件写入 SQLite。检查点只在结果持久化事务提交后推进；已提交步骤永不重放，只有未提交且冻结契约仍匹配的幂等步骤可自动恢复。
6. 崩溃时处于活动状态的非幂等步骤进入 `outcome_unknown`。用户必须确认潜在副作用后才能重试；人工决策和审批采用条件更新，重复或并发提交只有一个成功。
7. Studio 提供模板、JSON 编辑、静态预览、版本、运行历史、时间线、审批、人工选择、暂停、恢复、取消和事件审计。外部导入仍按不可信数据处理。

## 结果

- 可重复科研流程有明确的定义版本、执行事实和恢复语义，同时不限制普通聊天处理其他任务。
- 当前没有拖拽画布和节点并行；串行执行优先保证确定性与副作用边界。
- Tool 版本变化不会静默改写历史 Run，旧冻结契约只能按明确兼容与恢复规则处理。

## 重新评估条件

- 引入只读节点并行、子 Workflow、远程执行队列或第三方 Workflow 市场。
- 需要新的 Schema 大版本或跨版本迁移执行中的 Run。
