# ADR-0025：聊天附件与项目知识库显式分离

## 上下文

P4.6 的聊天附件和 P5.1/P5.2 的知识索引最初共用导入完成回调，导致每个可解析附件都会自动成为跨会话知识源。临时日志、待检查表格或只服务于单轮问题的文件因此可能污染后续文献检索。

## 决定

1. Attachment 只表示项目内已保存、可供消息和文档工具读取的原件，不隐含知识库成员资格。
2. `knowledge_documents` 是项目知识库的显式成员清单。只有知识库窗口导入或未来等价的明确用户操作可以创建该记录。
3. 聊天框选择或拖放文件只执行保存与本地解析，不调用知识索引队列。
4. 索引缓存重建、算法版本升级和影子索引激活只遍历 `knowledge_documents`，不能扫描项目全部 ready Attachment。
5. 移出知识库会从所有 active 索引删除对应 Chunk 和 FTS 项，再删除成员记录；Attachment 原件、解析缓存和历史消息引用继续保留。
6. 升级前已经存在的 Knowledge Document 继续视为用户知识库成员，不自动清空或降级。

## 理由

- 临时聊天材料不会改变项目长期检索语料。
- 同一附件可先用于对话，之后再由用户显式加入知识库，SHA256 去重仍然有效。
- 成员清单同时约束正常导入、缓存恢复和索引迁移，避免后台路径重新引入隐式索引。

## 负面影响

- 用户需要在知识库窗口额外执行一次导入，才能获得跨会话检索。
- 移出知识库不会立即回收附件原件空间；附件生命周期和历史消息引用清理由后续独立策略处理。

## 重新评估条件

- 后续可增加“把当前聊天附件加入知识库”的显式快捷操作，但默认值必须保持关闭。
- 若增加多个命名知识库，成员关系应扩展为独立 Collection，而不是重新绑定到 Attachment 导入流程。
