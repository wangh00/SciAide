# ADR-0026：可选 Embedding 与混合检索

## 上下文

P5.2 的 FTS5/BM25 能稳定处理术语、标题、标识符和原文关键词，但对近义表达、改写以及中文查询英文文献的召回有限。直接把本地模型打包进桌面程序会显著增加安装体积、运行时依赖和硬件差异，也会让未选择语义检索的用户承担额外成本。

## 决定

1. 默认保持 `bm25_only_v1`，未启用时不发出任何 Embedding 请求，也不要求模型或额外运行时。
2. P5.3 只接入 OpenAI 兼容 `POST /v1/embeddings`。配置包含 Base URL、Model ID、可选 API Key 和超时；API Key 只进入系统凭据库。
3. 用户启用并保存配置时，用单条测试输入验证接口并记录实际向量维度。配置未验证成功不得启用。
4. IndexVersion 持久化 Embedding Model ID、维度、配置指纹和混合策略。指纹包含 Base URL、Model ID 和维度，不包含密钥；任何身份变化都创建独立影子索引。
5. 归一化后的 float32 向量以 BLOB 保存在项目本地 `index-vN.db` 的 `chunk_embeddings`，全局数据库只保存配置与索引元数据。
6. 混合搜索使用 Reciprocal Rank Fusion 合并 BM25 与余弦相似度排名，保留每篇文档最多 3 条，并去除来源范围高度重叠的片段。
7. `builtin.knowledge.search@2` 支持 Document ID 和格式过滤。最终 ToolResult 继续受 8,000 rune 总预算和 900 rune 单片段预算约束。
8. 查询 Embedding 失败时立即回退 FTS5/BM25；影子索引构建失败时继续保留上一版 ready 索引，不能暴露半成品向量索引。
9. 查询向量缓存在同一项目、同一 IndexVersion 的 `query_embedding_cache`。缓存键为配置指纹与去除首尾空白后查询文本的 SHA256，不保存查询明文；最多保留 512 条并按 `last_used_at` 执行 LRU 清理。

## 理由

- BM25 和 Embedding 互补：前者保留科研术语、数值和标识符精度，后者补充语义与跨语言召回。
- 通用 HTTP 接口让用户自行选择本地服务或远程服务，SciAide 不绑定具体模型运行时。
- 模型、维度和服务身份进入 IndexVersion，可以阻止不兼容向量被静默混用。
- RRF 不依赖不同检索器分数处于同一数值尺度，适合 Provider 不透明的通用 Embedding 接口。
- 查询向量与文档过滤条件无关；项目本地缓存可让同一查询在切换格式或文档过滤器后继续复用，同时避免跨项目泄露检索行为。

## 负面影响

- 当前向量候选在 Go 中扫描项目索引，适合小型和中型项目；大规模语料需要后续接入专用向量索引。
- 不同 Embedding 模型可能需要特定 query/passage 前缀，当前通用接口不自动猜测模型模板。
- 启用或更换配置需要重新计算全部显式知识库成员的向量，可能产生本地算力或 API 成本。

## 重新评估条件

- 固定语料规模使向量扫描延迟不可接受时，引入 `VectorIndex` Port 或 SQLite 向量扩展。
- 主流本地运行时无法提供兼容接口时，再评估内置 ONNX/GGUF 推理；不得让该依赖成为 BM25 基线的启动条件。
