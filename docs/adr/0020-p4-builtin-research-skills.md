# ADR-0020：P4 内置科研 Skill 的发布与覆盖规则

## 状态

已接受，P4.5 实施。

## 背景

P4.1～P4.4 已支持本地 Skill 的校验、安装、项目启用和 Run 级不可变注入，但全新安装仍没有可直接使用的科研 Skill。内置内容不能通过绕开安装器的文件复制获得更高信任，也不能在应用升级时静默覆盖用户同 ID、同版本的包。

## 决策

1. `literature-reading@1.0.0` 和 `academic-writing@1.0.0` 的规范原件通过 Go `embed` 只读打入应用二进制。
2. 启动时把嵌入字节写入随机缓存目录，再复用 P4.2 的复制、Manifest/SKILL.md 校验、哈希、来源 ZIP 归档和原子激活流程；不直接把嵌入字节写入已安装目录。
3. 内置来源以 `source_kind=builtin` 持久化，仍记录来源哈希和私有归档。这样运行中的 Run 在包被替换后仍可按不可变快照读取原版本资源。
4. 目标版本缺失时补装；内容完全相同时只补齐或核对来源记录；同 ID、同版本但内容不同的现有包始终保留，不自动替换。内置内容变更必须发布新的语义版本。
5. 内置原版不能直接卸载。用户可按项目禁用，或通过 P4.4 显式确认，把同版本替换为自己的包；替换后来源变成普通文件夹或 ZIP，并恢复普通卸载语义。
6. 两个 Skill 只有项目显式启用后才进入 catalog。它们可按确定性 trigger 建议选择，也可由 `$literature-reading`、`$academic-writing` 显式选择。
7. P4.5 只依赖现有 `builtin.workspace.list` 和 `builtin.workspace.read_text`。不伪装 P5 知识库、PDF 解析或可信引用能力，不包含自动执行脚本。
8. Skill 正文强调证据边界、不可伪造引文和科研诚信；这些仍是任务指导，不是安全授权，也不能绕过 ToolRegistry、Plan/Full Access 或 Workspace 边界。

## 结果

- 新安装具有可立即启用的科研工作流，同时保持项目级选择权。
- 内置包与用户安装包共用一条受测试的供应链和审计链路。
- 应用升级不会以“内置”名义覆盖用户内容。
- 后续 P5 可以增加知识库和可信引用工具，再通过新 Skill 版本声明可选或必需依赖。
