# ADR-0033：P6.6 使用无密钥项目归档和隔离恢复

## 背景

P6 已把文献候选、附件、知识索引、可信引用、规范书目、证据矩阵、ArtifactVersion 和 ArtifactExport 串成项目级关系图。只复制全局 SQLite 会漏掉 Workspace 中的真实对象；只复制 Workspace 又会丢失 Run、引用和研究关系。直接复制正在使用的 WAL 数据库、打包全局配置或把归档覆盖回原项目，还会引入不一致、凭据泄露和部分恢复风险。

`.sciaide-project` 因此是项目迁移和灾难恢复格式，不是全局设置备份，也不是密钥导出格式。归档文件及其内部 HTML、JSON、SQLite、文献和 Skill 元数据始终视为不可信输入。

## 决策

1. 归档格式使用版本化 ZIP 容器。`manifest.json` 固化格式版本、应用/数据库版本、源项目摘要、项目 SQLite 快照、文件路径、类型、大小、SHA256、统计和 Skill 绑定哈希；Manifest 声明的数据库或必需对象缺失时失败关闭。
2. 数据库通过 SQLite 一致性快照生成，只保留当前项目及其 Conversation、Run、Tool、Attachment、Knowledge、Research、Bibliography、Evidence、Artifact 和导出关系。真实附件、文档缓存、知识索引及 Artifact 对象按 Manifest 显式枚举，不能通过扫描任意 Workspace 文件进入归档。
3. API Key、模型自定义 Header、MCP Server/Secret、识图渠道、Embedding 凭据和查询向量、权限 Grant、pending Approval、Skill 包源码及可重建临时缓存不进入归档。历史模型身份只恢复为禁用占位且没有可用 Secret；Conversation 权限恢复为 `Plan`。
4. Skill 只在 Manifest 中记录 ID、版本、内容/包 SHA256、启用状态和优先级。恢复时仅重新绑定本机已安装且哈希完全匹配的版本；归档不携带或执行 Skill 包，缺失项进入恢复报告，由用户显式安装。
5. 导入先在随机隔离目录中完成 ZIP 条目数、压缩/展开大小、压缩比、路径规范化、大小写碰撞、Windows 设备名、控制字符、尾随点/空格、符号链接、Manifest 和 SHA256 校验。归档条目必须与 Manifest 一一对应，未知或缺失条目均被拒绝。
6. 隔离数据库必须是受支持的完整 SQLite 文件，并通过表类型、外键、项目身份、迁移名称和迁移 checksum 校验；View 不能冒充必需 Table。数据库和知识索引中的项目作用域 ID 在暂存区重映射，历史 Citation、Lineage 和证据内容快照保持生成时语义。
7. 恢复默认创建新 ID 的托管项目，不修改源项目或归档。Workspace 只有在文件、数据库和索引全部重写校验后才以操作系统原子 no-replace 发布；随后用单个事务合并全局 SQLite。合并失败会移走刚发布的 Workspace，不留下可见半项目。
8. Windows、Linux 和 macOS 使用各自的原子“目标必须不存在”文件系统原语。Artifact 下载、正式导出下载和项目归档导出也复用该发布能力，避免“先检查、后重命名”竞态覆盖用户文件。
9. 发布前写入恢复 marker。启动恢复会清理中断的归档暂存目录；已提交项目移除 marker，数据库未提交的孤立 Workspace 移入可恢复 trash，而不是静默保留或覆盖。

## 结果

- “备份 → 干净数据根恢复 → 再备份”可以验证项目关系、对象 SHA256 和不可变历史快照，而不依赖原机器的凭据或全局配置。
- 同一归档可多次恢复为彼此独立的新项目；原项目和归档始终保持不变。
- 损坏、篡改、压缩炸弹、缺失 Blob、磁盘不足、数据库合并失败和发布竞态不会产生半恢复项目或覆盖用户目标。
- 缓存也可随项目迁移以保持即时可用，但它仍是派生数据；归档体积会因此增大。后续格式若改变包含范围或关系语义，必须提升 schema version，不能静默解释旧归档。

## 重新评估条件

- 若未来支持增量、加密或跨设备同步，需要单独定义基线链、加密密钥恢复、并发冲突和删除传播，不能在 schema 1 上隐式扩展。
- 若未来允许归档携带第三方 Skill 或配置，必须经过独立签名、信任和显式安装流程，不能在项目恢复时自动激活代码或凭据。
