# ADR-0027：Run 绑定的可信引用与证据快照

## 上下文

P5.1～P5.3 已能跨文献返回带页码、段落或 Sheet 定位的检索片段，`tool_results.citations_json` 也会保存工具候选来源。但候选来源不等于模型最终使用的引用：模型可能不引用某个候选、改写标记、重复标记，甚至生成并不存在的引用。知识索引重建或文档移出后，历史回答仍需要保留生成当时可核验的证据。

## 决定

1. `builtin.knowledge.search@3` 为每个有界证据片段生成 Run 绑定的稳定标记 `[K-XXXXXXXXXXXX]`。标记由 Run ID、IndexVersion ID、Chunk ID 与原文 SHA256 的组合哈希前缀派生；同一证据片段重复出现时保持一致，不同 Run、索引版本或原文快照不可复用。
2. 工具候选保存项目、IndexVersion、Document、Attachment、Chunk、定位符、来源范围、原文快照和原文 SHA256。模型可见文本明确要求只使用工具返回的完整标记。
3. 回答完成时重新读取该 Run 的全部成功工具结果，只接受 `builtin.knowledge.search` 产生、身份一致、原文哈希有效且确实出现在最终回答中的标记。重复标记只保存一次，伪造、变形、跨 Run 或冲突标记不进入正式 Citation。
4. 正式 Citation 按 Assistant Message 持久化，并保留回答中首次出现的顺序。Assistant Message 正文、正式 Citation 和 Run 完成状态在同一个 SQLite 事务中提交；失败时三者全部回滚，完成后不提供替换正式 Citation 的应用接口。记录外键绑定 Message、Run 和 ToolCall，但不外键绑定可重建的知识文档或索引版本，避免索引升级和移出知识库级联删除历史证据。
5. 同一 Chunk 因不同查询产生不同的有界 snippet 时，每个原文快照取得独立标记；模型引用哪个标记，正式记录就保存对应快照，不以最后一次检索覆盖较早证据。
6. 前端只把已持久化的引用渲染为可点击编号，并展示来源、定位、原文和证据哈希。形似 `[K-...]` 但未验证的文本必须显式标记为未验证，不能伪装成可信引用。
7. 不改写模型回答正文。引用校验失败只影响可信展示与持久化，不由客户端替模型补造引用。

## 理由

- 候选、使用和展示分层后，可以区分“检索到”与“最终引用”。
- Run 绑定阻止模型从旧对话文本复制一个看似有效的标记。
- 原文哈希绑定阻止同一 Chunk 的不同检索窗口共用标记，保证点击引用看到的就是该标记对应的证据快照。
- 证据快照让历史回答在知识库重建后仍可审计，同时不依赖旧索引文件长期存在。
- 只信任内置知识检索工具，避免 MCP 或普通文本伪造本地知识证据。

## 负面影响

- 引用原文会占用少量全局数据库空间；当前受检索单片段和总结果预算约束。
- P5.4 只展示保存的证据快照和定位符，尚未提供 PDF 页面的原生跳转或 OCR 区域高亮。
- 没有使用精确标记的模型回答不会自动获得正式引用，客户端不会通过模糊匹配猜测来源。

## 重新评估条件

- 引入 PDF 原生阅读器后，为 Citation 增加页内坐标和高亮区域，但保持现有文本定位兼容。
- 导出带参考文献报告时，从正式 Citation 生成脚注或尾注，不直接解析未验证的回答文本。
