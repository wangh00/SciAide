# 科研模式：聊天式研究助手增量开发

更新：2026-10-08。当前实施依据是本节；下方早期方案仅保留历史接入点和验收参考。用户已在当前对话确认从“方向准入与强校验优先”转向“提高科研能力上限与底座可扩展性”。不恢复旧工作台实现。

## 当前产品原则

- 保持原聊天瀑布流、原输入框与交互式对话。理解、必要澄清、计划、工具活动、主要结果、追问与修改都沿现有消息流呈现，不新增工作台、重复侧栏或平行执行体系。
- 用户自由表达，内部识别可组合的研究意图，不要求用户选择分类。方向是规划建议和方法资源，不是硬编码准入白名单；无需穷举全部方向才开始扩展。
- 区分成熟流程、通用工具可尝试、缺少关键条件。透明说明局限，不把未经验证的尝试当可靠专业结论，也不因没有方向名称就拒绝已有工具能完成的工作。
- 优先增强材料与产物承载、阶段内探索、已有结果复用和连续研究。避免每增加一种方法就修改主执行器。
- 计划允许调整。目标和授权范围内的补读、诊断、技术调试尽量不断打断用户；关键研究假设/方法、目标、数据用途或重要权限变化再解释并确认。
- 检查帮助定位问题，区分执行失败、科学疑点与探索未完成；不新增万能科研裁判或大量方向专属硬门禁。保留已有安全、授权、文件完整性及版本保护。
- 研究记忆在现有 workflow/run/conversation 与产物版本体系内持久化，不能只依赖聊天文本，也不另造 task/attempt/job 体系。

## 增量顺序

1. 审计现有入口、工具循环、计算输入输出、成果和返修依赖；纠正对底座能力的误判，先解决阻碍已有能力使用的小问题。
2. 逐步增强多类型材料、多产物、已有代码和结果的读取复用；基于真实需求设计适配点，不先铺设所有语言或专业工具。
3. 在原执行链增强阶段内探索和计划局部调整，支持比较方法及增量更新，保留前一版本和来源关系。
4. 建设可组合能力描述与按需发现；方向资源帮助 AI 找方法，工具权限仍遵循实际授权。
5. 用连续对话案例检验扩展性：文献比较后补证据；数据分析后比较另一种方法；已有代码复现后修改。过程始终在原聊天流完成。

每次交付区分源码/自动化夹具/真实模型/原生桌面验证。开发期不擅自覆盖正式 EXE；用户明确要求提供可运行版本后按 AGENTS.md 覆盖原路径，不直接改用户数据库推进状态，也不把测试构建宣称为真实案例验收完成或对外发布。用户不需要新建 Codex 聊天；涉及新版路线验证时建立隔离的新科研任务，不改写历史冻结路线。

### 动态分配的准确含义

动态路线和动态调用是两层：AI 可在方向允许的方法/阶段中提出路线；执行时每个阶段的模型可基于结果继续选择允许工具。宿主负责限制，不负责假造一串预排调用。

工具集应由“方向/方法上限 ∩ 当前阶段允许范围 ∩ 用户确认范围 ∩ 当前可用工具”计算，再叠加资源作用域、审批与预算。只在合法范围内调用，不因工具发现、Skill 内容、MCP 列表或 Full Access 选择就绕过方向边界。需要扩大研究范围时回到变更确认，不能热改当前执行快照。

典型验证例子：
- 指定论文且明确“不额外检索”：只能读选中文献和必要资源，不能从检索工具绕到网络或其他项目材料。
- 用户明确需要补充检索：先核查该方向已实现哪些检索/筛选/引用检查，按确认范围提供工具；不把“可搜索”宣称成“系统综述完整覆盖”。
- 已有表格分析：按已确认方法开放所需数据与计算工具，检查环境、代码执行审批和数值结果；报告阶段不能随意换数据或重算另一种方法。
- 方案草案：允许辅助设计所需资料工具，禁止伪装已招募、实验已执行、伦理已批准或已获得结果。
