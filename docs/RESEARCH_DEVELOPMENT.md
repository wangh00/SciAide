# 科研模式开发

更新：2026-11-12。区分已确认产品方向、设计建议与当前实现；具体完成度、最近测试与构建身份只在 [开发进度](PROGRESS.md) 维护。系统边界见 [架构](ARCHITECTURE.md)，不再保留逐轮修复日志与过期实施命令。

## 一、产品方向

**科研模式以能围绕目标、根据证据调整路径的研究助手为主；固定路线是明确任务的可选执行模板，不是所有科研请求的默认必经流程。**

2026-11-12用户确认上述定位，并要求科研模式与普通对话有用户可感知的区别、提供科研专属工具。以下模式边界与工具方案为目标设计，不表示动态探索、界面或工具组合已经实现；现状仍见第二节与[开发进度](PROGRESS.md)。

1. 保持原聊天瀑布流与同一执行底座；通过研究状态、专属工具和材料/产物视图区分模式，不另建独立科研聊天系统或第二套科研执行器。
2. 用户不需要一开始写完整提示词。可以先问候、解释文件、讨论方向；AI 仅在缺失信息影响工作时提出简短问题。
3. 真正需要用户选择时，在当前位置展示问题卡；选项、自由补充和确认在卡片内完成，多问题连续切换，不每问一次弹一个窗口。
4. 研究目标和交付物足够明确且用户希望推进研究时，AI 可以调用规划工具；**规划不等于执行**，采用路线仍由用户确认。
5. 产出后仍可以正常追问。解释不自动返修；改变目标、材料或方法时，在原对话提出一次明确返修方案，确认后执行。
6. 不把“文献比较 / 数据分析 / 研究设计”变成学科白名单。它们是表达示例；真正上限取决于已实现工具、材料、方法和运行环境。
7. 优化应减少信息丢失和重复操作，而非不断增加科研硬门槛、强迫用户手写内部字段，或用放宽引用校验掩盖缺陷。
8. 科研模式执行任务默认采用 `Full Access`，以免文献、资料和计算路线在逐工具确认中被无意打断；用户仍可在启动前明确切换为 `Plan`，且 Full Access 继续受工具 Schema、Workspace 路径、超时、取消和科学门禁约束，已冻结任务不自动升权。

### 与普通对话的产品边界

普通对话也可以查论文、读文件或写代码；区别不是把这些能力人为独占，而是科研模式持续维护一项研究及其可核验成果。

| 用户可感知的区别 | 科研模式的目标行为 |
| --- | --- |
| 持续研究对象 | 明确当前问题、目标与约束，保存材料、假设、证据缺口、决策及结果；不把完整聊天流水当研究记录 |
| 可解释的主动工作 | 展示正在做什么、为什么、下一步及其依据；短期计划可随证据更新，阶段标签不等于必经节点 |
| 可复核的成果 | 结论关联实际来源或计算，区分事实/假设、摘要/全文、已核验/待核验；报告不是每次对话的必填产物 |
| 明确的控制与边界 | 用户可暂停、补充或调整目标；材料使用、费用和外部操作遵守当前授权，重大范围/验证方案变化需相应确认 |

科研任务内仍可自然讨论、解释术语或直接回答简单问题，不因切换模式就强制提问、联网、生成路线或运行完整链。已有授权内的局部动作应可基于新证据主动改变，不必先制造失败再返修；改变研究目标或事后更换验证标准不得冒充普通应变。具体调整协议尚待设计，不静默改写旧任务的冻结契约。

### 科研专属工具与可见交互（建议，待验收）

工具是按需组合的研究能力，不是另一组必跑阶段；优先复用现有来源、材料、计算和审查底座。下列为能力契约，不是当前可用工具清单：

| 能力 | 应形成的研究资产与边界 |
| --- | --- |
| 文献发现 | 专业来源查询、检索范围和来源记录；区分题录去重、版本线索与独立研究确认，不默认声称穷尽 |
| 论文核读 | 可定位的摘要/全文、方法、结果及图表依据；未读、无法访问和原文未讨论分别保留 |
| 证据比较 | 研究之间的支持、反对、差异与未知项；证据表按当前问题组织，不固定套用所有学科字段 |
| 数据实验 | 资料检查、分析/模拟代码、运行环境与结果版本；保留原数据及可复现关系，不为得到期望结果改方法 |
| 研究方案比较 | 假设、替代解释、变量/测量与可行性权衡；能指出不可识别或缺数据，不替代伦理、领域或统计批准 |
| 研究记录与审查 | 保存关键发现、否定结果和决策理由；对具体主张、数字、来源及交付范围做必要核验，不把阅读进度当科学通过 |

建议在原对话中持续显示科研身份与轻量研究状态，默认只突出“当前问题、正在做什么及原因、下一步”；材料/证据、产物、历史与实际资源用量按需展开，并提供可见的科研工具入口和操作结果。具体布局、命名、入口及工具粒度尚未确认；不以额外长表单、更多调用或独立页面数量制造模式差异。普通对话转为研究任务应明确展示承接目标和选用材料，不把一次闲聊或上传自动当作执行授权。

## 二、当前交互与执行流程

### 讨论和开局

- 研究方案页保留居中入口，历史方案按需展开；进入任务后继续使用原聊天输入框。
- 开局选择附件先暂存，点击开始讨论才进入任务；选择文件本身不启动研究。
- AI 根据语义决定直接回答、读取文件、调用 Skill、提问或设计路线，不要求固定先回答一套问卷。
- `builtin.research.plan.prepare` 使用完整协商目标启动原规划链。它不会执行研究；路线卡中采用后才编译、冻结和推进。
- 路线需要表格时可选用同一任务已发送的合适文件，不强迫重复上传；用户仍核对并点击采用，宿主不擅自把附件绑定为计算数据。

### 执行、交付与后续对话

```text
讨论 ↔ 问题卡 / 资料读取
  → 需要研究且目标明确 → 候选路线 → 用户采用
  → 按路线执行 / 必要人工选择 / 计算或证据处理
  → 交付稿 → 独立审查
       ├─ 合格 → 后续问答 / 用户登记产物
       ├─ 具体可修问题 → 原返修确认 → 受影响阶段 → 再审查
       └─ 真正缺用户决定或材料 → 明确问题卡 / 指明材料 → 继续原链
```

这不是固定节点清单：有些任务只读文件，有些只设计方案，不应强制加文献检索或 Python。

- 左侧展示当前轮路线；返修从确认起点展示后续阶段，有历史轮次时可以查看历史路线。
- 科研阶段借用普通 Agent 工具循环，但使用冻结的阶段输入、工具集合和任务资源范围。
- 普通阶段从首轮可正式提交，不再只能等待探索收口；v9 按材料字段定位、宿主阅读进度与旧路线兼容减轻无目标重复阅读。四轮收口仅保留为最后保护，不代表证据充分或审查通过；协议、预算和保留边界统一见 [提交接口](ARCHITECTURE.md#提交接口与明确拒绝)。这还不是任意科研任务的自动工作单元拆解或模型成功保证。
- 引用选择、执行授权和科学选择是不同决定。回答问题不自动授权重算；上传附件不自动修改旧报告。
- 数据输入绑定、代码、执行结果和报告分别保留身份；旧计划中“还没上传”的描述不能推翻已绑定数据事实。
- 当前终态续聊/返修仍以未登记交付为边界；已登记产物暂不能在原任务内返修。取消或传输失败应走阶段恢复，不冒充科学审查返修。这些限制是现状，不是最终产品目标。

## 三、审查与返修应怎样工作

### 文献综合的提交纠错

科研模式是应用的证据与交付约定，不是要求模型改变身份。纠错阶段使用原生必选工具通道，但保留局部修正和完整科学重交两个独立选择；不新增科研必填项、不额外放大修正预算。完整重交重复错误摘录时应明确指出未修正，优先让模型选连续原文 ID，不能靠补空格或改写来源过检查。

新编译动态文献路线将原文选择前移到综合首次提交及完整重交：模型保留科研判断，只明确选择当前签发来源中的连续原文，程序复制后仍执行原 700 字符限制、来源与科学检查；不是自动裁剪或失败后增加一次兜底。旧冻结路线不静默升级，逐文档分组契约不改。版本、实际可见性与原文保全只维护在[提交接口](ARCHITECTURE.md#提交接口与明确拒绝)，本机夹具与真实模型验收分别见[开发进度](PROGRESS.md#文献综合首次原文选择2026-11-06)。

新 v2 还允许针对同一失败稿明确替换完整顶层字段：例如只改摘要，或一并更正引用判定与推荐，不再为每个小修正强制重写整份综合。未涉及的字段保留，合并后仍执行全部校验和原两次修正上限；它减少引入无关新错误的机会，**不保证模型判断收敛，也不自动把题录改为排除或将摘要截短**。协议、基线/审计和兼容性只见[提交接口](ARCHITECTURE.md#提交接口与明确拒绝)；结构化选源与自然语言理解的边界只见[来源契约](NETWORK_BROWSER.md#文献来源与能力契约)。

普通阶段提前提交的格式失败也进入共用通道，不能只为文献综合特判；规划的真实 Skill 加载、分段代码和局部修正仍保留各自边界。格式错误不等于科学否决，精确分类和提交通道的实现约定统一见 [系统架构](ARCHITECTURE.md#提交接口与明确拒绝)，真实模型可靠性仍单独验收。

模型明确拒绝继续时立即停止本轮纠正，分别保存拒绝原文与前次未解决的引文/范围等问题，不再把拒绝笼统说成格式修正耗尽。空原生拒绝也不自动重连。进度文本仍沿有限纠正；科学否决仍沿原返修；普通聊天不受此执行分类影响。用户可核对服务后显式重试原阶段，重启不会自动重发。

格式、引用身份与库存仍需先可验证；在此基础上，范围声明和多条引文的独立问题应一次交给模型，而不是每轮只揭示前一个。不能将“共两次修正，分别碰到不同错误”描述成“同一引文已纠正两次仍不对”。格式失败后转入现有专用提交接口，保留已完成工具结果，不重新探索。

纯引文错误继续使用原精确选段/手写摘录接口；范围与引文混合错误在同一哈希基线下允许模型明确提交 `evidenceScopeUpdates`，且只含冻结 Schema 原有的 `evidenceGaps` / `coverage` 完整替换值。这个字段只属于当前局部修正协议，不进入保存的科学产物，不给全部模型结果新增必填字段。其余结论、判定、推荐或来源变更仍提交完整结果。未提及字段保留，合并后完整验证；旧拒绝原稿和原文不改，不扩大两次修正预算。

精确原文选段用于避免 HTML 实体、原文粘连等被模型重抄时悄然改写，不通过模糊匹配自动补空格或改词。候选摘录可用于片段级判断，但不能冒充实际原文工具的核读范围收据。效应量、置信区间、全文或调节因素只有确属用户/已确认契约核心交付时才标核心缺项，不能因列入提取表便升级目标；语义判断仍需真实模型验收。

当前共用执行底座将“科研判断”和“程序机械信息”分开：审查者提交科学判断、每条问题和执行建议，程序生成既有分类/关联位置并绑定当前输入摘要。模型不再被要求抄写 SHA-256；明确提交错误摘要仍拒绝，不能因此覆盖科学结果或历史。现有问题定位与局部纠错保留，不新增重试次数。

恢复动作由后端统一提供给原瀑布卡：本地门禁仅重试核验；发布失败仅恢复发布和导出；AI 中断明确提示再次调用模型；确实需要返修才显示原返修操作。无效、过期或不属于当前失败阶段的动作不能执行，输入前置缺口不能通过重跑相同计算解决。没有新增 AI 整理方案的中间步骤。

协议故障卡不是独立审查结论；重试范围、网络流无法续传、已保存分件复用与后续费用见 [恢复架构](ARCHITECTURE.md#3-三种模型协议与恢复分层)。报告/独立审查的新执行区分候选记录、来源报告、入选文档与独立研究数，合并须有映射；分别检查派生比例的算术、分母/分析单位和外推有效性。不以未在原文逐字出现判定正确推导为捏造，也不以算术正确放行不当外推；缺失的既定交付仍需返修。不改历史报告、冻结验收或实现检查点哈希。

入选文献的分组分析完成后，全部已接受分析与原始摘录进入全局综合。已授权任务读取时，准备阶段仅按既有持久化快照容量检查，不因整个 JSON 超过旧 220 KiB 字节阈值提前停止；后续由通用投影与模型实际窗口决定分页，普通 finding、候选摘录和返修历史同样受支持，不只处理长 workProduct。未授权读取、实际模型窗口确实容不下必要要求、或超出存储容量仍不能绕过。现代 `document-analysis-v1` 检查点按文档科学输入和来源指纹复用，旧检查点仅匹配原 `sourceKey`；均不重写历史或自动批准科研结果。

共用底座验收入口为 `scripts/test-research-foundation.ps1`：受控模型/临时库覆盖讨论、设计、计算、文献返修、问题卡、三种协议、长材料和真正的报告发布/导出/重启恢复。CI 仍运行完整项目测试；脚本不是只测门禁，也不代表真实模型科研判断已验收。

独立审查针对**当前采用路线承诺的交付物及成熟度**，不是对所有科研任务套最终论文发表标准。草案未完成验证与草案正文根本不存在是两种情况；前者可以是已确认边界，后者仍是缺项。

| 发现类型 | 合理处理 |
| --- | --- |
| 门禁绑定/工具执行等技术失败 | 保留已完成审查，原卡“重试交付核验”只重跑本地核验；不当成科研否决或要求用户重述问题 |
| 现有证据已在任务内，只是没读到 | 定位并核读保存记录，不把未读当缺失，不要求重传 |
| 报告漏写筛选理由或书目错配 | 复用保存事实、修正文稿；不要因此重做正确方法与计算 |
| 实际代码、方法或数据使用错误 | 回到真正负责的阶段，明确影响和重算范围 |
| 公开资料有待核查 | 在暴露工具与范围内补查；访问失败说明限制，不假装查到 |
| 私有材料不可访问或目标存在真实冲突 | 提出简短明确的问题；保留其他 AI 可完成的修正 |
| 用户只是问结论或打招呼 | 正常回答，不新建路线或触发全任务审计 |

工作流本地工具消费完整持久化快照，不消费模型提示。绑定输入和工具服务共同遵守已有 1,048,576 个 Unicode 字符的快照上限，模型生成的普通工具参数仍为 256 KiB；不能只放开绑定、随后在工具服务再次失败。本地核验不要求模型分页权限、不截断审查原文，Schema 与冻结依赖/哈希验证不变。模型阶段另按窗口与既有读取能力投影；多字节材料已适配视图时不要求一定发生缩短。

门禁只有明确业务错误 `RESEARCH_REVIEW_NOT_APPROVED`（或明确旧版否决信息）才进入原建议返修；技术错误仅恢复门禁，先复验当前依赖，不能拿过期审查放行。核验完成后的科学缺项仍需按原建议从责任阶段修正，技术恢复不意味着报告通过。

当前实现已提供：稳定审查问题跟踪、单源 findings 提交、原建议直接返修、起点与后续范围展示、同执行问题卡，以及报告—证据—书目—责任结果的导航。新报告会确定性追加已保存筛选记录与实际引用书目；附录不是新的科学证据。

新报告输入冻结 `host-report-assembly-v1`：附录标为程序管理的记录；有 `query-candidate-audit-v1` 时按实际查询快照列来源记录数、候选数、组内额外记录数及归属/标识，逐查询计数，不能相加为独立试验数。没有该记录时不推断去重规则或前后计数。审查复用报告同一审计快照；完整归并图不进入证据分批预算或续跑 sourceKey。连续完全相同的程序附录可确定性去重并保留原始提交及变更审计。旧报告按旧输入重现，不回写历史。审查的 `reportComposition` 只描述与生产阶段冻结记录逐字核对的附录范围（Unicode 字符位置、哈希），不是科学证据或“谁最初键入”的证明；不能因这些段落存在而要求 AI 删除后再被程序追加。

逐文档分析可选 `workProduct` 保存本轮实际完成的评价表、关系核对及其他研究产物，不为所有方向强制 RoB/AMSTAR 字段。`evidenceWork` 将当前已完成分组/direct 分析完整交给方法、报告、审查；保留未知项及其理由，不能以未来待办冒充完成，也不能把分析阶段未采用引用当报告已采用来源。长工作原文仍完整保存；有既有任务读取权限时，模型视图给 `evidence-work-pages-v1` 原输入字符范围/哈希/路径，沿原分页工具按需核读，不扩大权限或删除独特材料。通用冻结输入还支持 `stage-input-pages-v1`：在实际模型预算中预留工具、提交及纠错空间，优先把来源库存、审计和历史投影为原件读取导航，不删除原件，不改指针/哈希；当前目标、验收与执行决定保留。成功新增分页与研究探索分开计数并有总上限，重复/失败不能延长额度；工具预览缩短时只按可见内容推进 offset。极大原要求、Schema 或累计独特材料仍受有限窗口约束，不宣称容量无限。

“有限证据继续”仍只确认引用与草稿边界，不自动改变验收。用户明确协商交付范围时，可在**同一张原对话返修卡**展示宿主读取的原条件和完整新条件；只在确认后派生后续报告/审查的 `researchContract.successCriteria`。原研究问题、材料、方法和历史不改，后续普通返修保留当前确认范围；暂缓工作必须披露，真实性检查不豁免，不新增整理方案按钮。审查若建议“无法核实则披露”，须明确披露能否满足当前约定；不能满足时指向真实可执行补证或明确的用户范围决定，不能承诺同样材料反复综合会消除缺项。

新绑定审查使用 `report-review-parts-v1`：`context.markdown` 仅是正文，`reportRecordAppendices` 按顺序保留程序记录原文；二者拼接逐字符还原完整报告，原产物与 UI 不变。返修基线、依赖及登记核验仍针对完整报告，不能因分离视图丢失附录或漏审科学内容。附录实际文本可作为定位依据，组成元数据不是科学证据。误用旧正文路径时只给唯一精确附录匹配的定位提示，不自动改依据或判定。

审查依赖与最终发布共用 `internal/app/reportview` 还原逻辑，保持 Unicode 字符位置、段摘要和原始空白；发布仅核对本次采用的同运行成功门禁，并将完整还原报告与待发布稿比较。未知分离版本、损坏附录、变更后的报告或其他运行门禁仍拒绝。发布绑定失败是技术错误，不是科学否决；保留具体宿主诊断，原卡只重试发布阶段，不触发模型重新审查。验收必须覆盖真正的 Markdown/DOCX/PDF 导出，不能以门禁通过代替发布成功。

审查不再接收生成阶段的 `_reviewCorrections` 强制整改清单与重复旧稿；`reviewHistory` 完整保留稳定问题 ID，由模型核对当前内容后判 open / resolved / withdrawn。生成阶段仍收到原确认的整改目标，不能擅自删改真实问题。可选表达改进不应升级为必改，已改的问题不因历史仍存在而继续阻断。

新跟踪审查使用 `claim-scoped-evidence-v1`：`evidenceGaps.required` 表示重要性，不直接代替交付判定。真实研究允许证据不足或不确定结论；是否缺工作应看原承诺和当前具体主张。用户明确要求的核验/分析未完成仍不能通过，虚构核读范围、原文误引、数值错误等原检查保留。旧冻结验收输入保持旧语义，不热改正式报告或旧返修卡。返修进度比较已确认前后的引用身份、采用判断、原句、来源级别及未解决字段，不用重试输入哈希冒充补证变化；这是有边界的提示，不证明全部来源已读，不自动禁止新研究或删除问题。

返修输入的 `revisionTargetCapabilities` 描述实际工具、采用数量和本地补查剩余额度。“提取可信证据”是引用选择，不负责查找新原文；缺失字段应定位到具备核读/保存入口的证据综合阶段。推荐全部采用不代表所有候选全部采用，更不代表全文已读。没有能力、额度已耗尽、全文不可得时必须如实说明，不能宣称重复执行会补齐。能力是计划依据，不按关键词强改科学 verdict、不新增 Schema 硬门槛或中间整理方案按钮；真实模型的路线选择仍需实测。

宿主不应根据 DOI 差异自动判论文错误、不应自动删除问题让审查通过，也不应靠关键词强制“只改报告”。AI 仍要读真实来源并给出判断；真正上游错误仍需上游修复。已有旧卡片与冻结审查不被后台热改。

返修的完整旧稿与执行中间进度必须分离：起点复用确认时已冻结的结果，下游只取确认前的完整结果；文献分组、原文核读及补查只累计进度，不能变成下一组的“旧稿”而使已完成分组失效。同一轮在取消/中断后手动恢复应继续未完成部分。新逐文档检查点不因综合修正文字或轮次变化整批失效：科学目标和同篇来源未变时复用已接受记录，覆盖综合可选 `documentAnalyses` 只替换确需修正的文档；仍校验当前库存、重复文档与同文档真实签发引用。目标/用户变更仍失效，新材料或索引影响对应文档。未知版本、哈希损坏及跨运行/阶段检查点不复用；不替旧任务补造新版身份。

### 真实需求、相对时间与报告分层

新规划将真实用户文本（排除 AI 回答及内部工作流消息）与 AI 整理要求分开，冻结 `userRequests` 和 `researchTimeContext`；采用路线时另交接已确认澄清，执行阶段提供 `userIntent`，不覆盖后续 `_userRevision`。长讨论沿原 `planning_discussion` 冻结记录读取，而非复制到每个阶段或以 AI 摘要冒充原话。发表时间的宿主解析与校验共用规则：例如冻结年份为2026时，“近十年文献”为2016–2026，“2015年至今”为2015–2026；都是含两端的年份宽边界，不是精确日期过滤，引文仍保留“至今”而不补写2026。明确年份、已确认变更优先，随访/年龄等不机械视为发表年限；支持范围与旧输入兼容只见[时间依据契约](ARCHITECTURE.md#1-一条应用执行链不建第二套科研系统)。其他含糊时间保留正常澄清，不加学科白名单。

审查指导区分实际约定的工作未做与现有证据不确定：允许摘要级说明不自动升级成全文、穷尽检索、专病点估计或长期阳性结果任务；未获取全文也不冒充已经尝试且不可得。这是来源交接和模型指导，不宣称可机械根除所有语义误判。

报告仍使用原卡片和聊天瀑布流，默认显示已有通俗说明/简版；没有对应章节时使用短正文或已保存的结论与局限，不要求所有科研方向新增格式。详细科学正文、已知程序生成的筛选/引用/检索附录分层挂载，代码围栏和普通科学附录不作为程序分界；后续科学章节仍留正文。报告原稿、快照、哈希及登记导出不受此显示投影影响，旧报告不被重评或改写。

### 实际方法记录与返修连续性

新检索在保存查询快照的同一事务中记录每条来源的实际归组决定（`record-grouping-v2`），收紧误并分支并保存有界判定见证。题录身份/材料类型线索与科学独立研究身份分开，完整契约只见[来源说明](NETWORK_BROWSER.md#文献来源与能力契约)。旧 v1 查询继续按其已保存规则说明，缺失决定不从当前书目回填；冲突记录独立保存，旧材料与历史不迁移、不重评。

报告附录由宿主按冻结记录生成实际方法说明与逐记录处理依据；审查复用同一份输入，不能将已保存方法误判为没有记录。复用既有来源只证明本次复用，不证明旧记录首次匹配分支；旧查询未保存的方法仍未知。来源归组不是独立试验身份核验，真实冲突与研究间重叠仍需科学判断。

返修审查除稳定问题 ID 外，携带前轮逐项 `acceptanceChecks`、原 `requiredCorrections` 与 `revisionPlan`。它们是历史判断和方案，不是事实证据，也不锁死上轮通过项。改判应区分新证据、返修引入缺陷与上轮漏审；若报告执行了原建议但仍不满足要求，应承认原方案不足，并说明真正能完成修正的结果和路径。要求实际工作时不能把“否则披露”写成同等完成条件，下一轮又因此否决。

报告阶段只能呈现已有方法记录和局限，不能生成缺失的历史执行记录。无可执行修正路径时说明真实阻碍，只对需要用户决定的范围/材料选择使用既有问题入口；不能泛化为全部返修都等待用户，也不能新加整理方案按钮。此处通过实际记录交接与审查指导改善，不新增语义硬校验、关键词放行或额外纠错次数；模型是否正确运用仍需真实案例验收。

### 文献身份纠错与运行记录维护

文献批次内的 `candidateAssessments`、`evidenceNotes` 必须引用当前冻结来源。身份诊断一次给出未知/重复/缺失 ID、具体字段路径和来源题名；只有条目完整、没有重复且未知与缺失数量对应时，才开放 `candidateIdentityPatch`。模型在当前集合允许的 ID 中显式选择，补丁绑定原候选 SHA256，仅替换已诊断 ID 字段；其他判断和摘录保持。合并结果仍做完整来源、原文与业务检查，不以 UUID 相似度替模型决定是哪篇论文。原两次纠错预算不变，不能靠追加重试掩盖不可操作的诊断。批次引用错误一次报告全部具体路径，而非只给前 8 处；不复制全部原文。

提交失败记录轮次、已用纠错次数、候选哈希和脱敏有界诊断，原始候选仍走既有持久化审计。模型服务明确以内容检查拒绝请求时，区别于科学否决和临时连接错误：不自动重复发送、不自动更换服务绕过；保留阶段进度，错误不代表研究主题违规。外部服务未给触发位置时必须说明未知。

删除只获取必要身份与终态，在同事务内复核同任务所有执行和活动对话，不预加载全文历史。外键索引与事件触发器覆盖任务/方案/项目删除入口；已登记产物不随运行记录删除。既有孤立事件由启动后台任务每批最多 1000 条扫描并让出数据库，取消关闭可中断，完成后记录维护标记；现存任务、未知事件类型不清理。该维护释放数据库页面供复用，不保证文件立即缩小，也不在用户前台执行 VACUUM。UI 分开显示删除中、删除成功但列表刷新失败，日志分段计时便于后续定位。

## 四、目前的瓶颈

### 1. 信息已经保存，但跨阶段仍可能使用不准确

“有记录”不等于模型看到了、理解了或正确关联了。当前已减少模型转抄书目、筛选理由和重复来源；已将查询归并事实摘要贯穿证据/方法/报告/审查，并提供冻结输入预算分页；跨研究方向的语义材料清单、产物可复用性仍需扩展。

**方向**：让模型拿到准确导航、版本和来源位置，必要时读完整原件；宿主处理确定性身份关联，AI 负责科研解释。

### 2. 超长独特材料仍依赖模型窗口

已分离讨论/执行、校准用量、预留最终提交/纠错预算，并对完全重复来源做共享编码。但独特资料、长稿、历史审查及多轮工具协议仍可能挤满上下文。

**方向**：在冻结输入与来源不变的前提下，逐步转为可寻址材料和按需读取；先验证回读、分页、重启和纠错闭环，不靠不断扩大窗口或摘要掉核心证据。

### 3. 科学判断与返修收敛不能靠程序完全保证

AI 可能误解成熟度、把不同论文当同一试验、重复提旧问题或建议过早重做。程序能保证身份、保存与范围，不替代方法学判断。

**方向**：保留实际来源与当前产物位置，区分已修/仍缺/新问题；以真实案例检查为什么返工，不增加一个“让 AI 整理返修方案”的重复回合。

### 4. 长任务的速度与内存仍需真实量测

已做流停滞识别、有界恢复、完整代码片段保存、分页视图、重复阅读收口和 renderer 故障恢复。正常长生成仍可能慢；故障注入或公开工具事件回放不等于真实模型速度、数小时稳定性或真实 OOM 已通过。

**方向**：分别记录模型生成、重试、压缩、读取、计算、审查耗时与宿主/WebView/Python 内存，不再只显示“处理中”。

### 5. 领域扩展不只是增加提示词

当前强项为文献证据、表格 Python 分析和设计型材料。Skill 可扩展方法知识，但原生 R/Julia、专门科研数据库、远程计算等仍需运行时与来源链接入。

**方向**：优先做可组合的材料、计算、产物和复现接口，再逐项新增科研能力；不宣称全部 311 个 Skill 都已原生可执行。

## 五、后续开发顺序

| 优先顺序 | 工作 | 用户应看到的验收行为 |
| --- | --- | --- |
| 0 | 研究助手定位与最小专属工具闭环 | 简单问题可直接讨论；开展研究时能看见目标、工具行动、依据与成果；新证据能改变下一步，不必先跑完整路线 |
| 1 | 共同输入/材料契约与有界闭环 | 需求解析与校验使用同一可满足的约定；缩减预算不把已分页材料重新展开；导航能经原授权接口回读；不满足时明确停止 |
| 2 | 当前交接修复的有界真实验收 | 简短输入可推进；不重复上传；正确旧结果被复用；报告返修不无故重算，并说明实际消耗 |
| 3 | 可追溯材料清单与按需读取 | 长资料仍可完整回读，缺失/未读区分，引用和版本不漂移 |
| 4 | 审查—返修收敛与跨轮增量更新 | 每个问题有当前产物位置；范围可解释；修过的问题不因交接丢失重来 |
| 5 | 长任务性能与资源治理 | 可解释的等待状态、可停止恢复；数小时滚动/多轮返修不持续增长到白屏 |
| 6 | 更广科研能力与发布加固 | 新运行时/来源/产物复用同一对话、权限与来源链，并有独立真实案例 |

这是优先顺序，不是预先承诺所有方向已经实现。先确认最小产品闭环及其共同材料/权限底座，不先扩充固定阶段；现有审查联合预算等已复现缺陷仍保留，不因调整产品定位而宣称解决。工程改进须经离线反例与组合回归，再在另行授权的固定范围/预算内验证，不把扩大额度或新增提示词当作效率问题已解决。验收方法只见[开发指南](development.md#科研模式收敛验收)。

两问题的同请求上限对照及新领域分配的工程/公开接口验证已完成，结果和局限只维护在[开发进度](PROGRESS.md#4-验证结果与边界)；尚不是独立研究、全文或金标准召回评测。实现契约只见[来源说明](NETWORK_BROWSER.md#文献来源与能力契约)。

1. **领域选源与预算分配（工程版已实现，模型判断待验收）**：新规划显式提交学科及理由，宿主固定安排来源槽位，保留调用方结构化选源并记录真实请求分配；教育配置没有因数据库名称而移除此前观察到相关题录的 Europe PMC。失败、限流、本地额度和计划边界分开。下一步评估模型能否从真实冻结需求选对学科/数据库限定，以及更广问题集中的新增与损失；不以两例接口成功批准默认策略的科学质量。
2. **先区分题录、版本、独立研究和伴随材料（保守工程版已实现）**：误并分支和有界待核实线索已通过受控链、公开题录离线回放及归档/回读验证，具体结果只见[开发进度](PROGRESS.md#4-验证结果与边界)。不把线索当独立研究确认，旧快照不回填；跨查询新关联、版本谱系及注册号/样本映射仍待设计实现；全文金标准和真实模型是否正确使用线索仍待验证。机构大学名称的人群假阳性仍是领域筛选评测问题，不宣称此次已机械解决。
3. **领域检索式与可复现测量（四题有限实测，完整质量仍待验证）**：语法投影/审计工程规则只见[来源说明](NETWORK_BROWSER.md#文献来源与能力契约)。扩至四个大学写作主题的真实采样显示：人群限定可减少部分学段假阳性，却不保证保留写作表现证据或补齐自评实施细节；另两库限流使完整对照仍缺失。实际结果、分离标注分歧和 partial 诊断边界只见[开发进度](PROGRESS.md#4-验证结果与边界)。发送前文本控制、客户端参数和顺序核对不是语义等价/来源过滤证明，模式声明及哈希也不独立认证真实性。下一步在新预算内先补缺失来源、全文人群/干预实施与实测结局，再扩大多学科及专家核对，评估广窄互补而不直接将窄式设为默认。元数据、代理一致率、旧响应或各库总命中数之和均不是专家相关性/总体召回验收，不让全网搜索代替题录检索。
4. **分离发现、定位与全文许可**：CORE 的注册额度、商业使用及全文权限先核验，再考虑独立 DOI 定位/开放版本获取；不把匿名提示、重定向或发现 URL 当成已下载正文。当前实现边界只见[来源契约](NETWORK_BROWSER.md#文献来源与能力契约)。
5. **提高使用效率而不牺牲证据**：在同一请求上限内评估分页、缓存/冷却和来源属性完整回读；长任务真实成本与最终引用正确性单独验收。真实模型、专家筛查和原生体验分别取证，不通过扩大纠错预算换成功。

## 六、验收原则

- 新科研助手设计先验证适应性与模式差异：简单问题不被迫开完整流程；新证据可在未报错时改变下一步；证据不足可明确停止或缩小结论；用户能辨认当前目标、工具行动、证据与未完成项。流程节点完成数不能替代这些验收。
- 自动化验证状态、协议、身份和恢复；真实模型验证对话、科学判断与返修效果；独立计算/人工核对验证产物；原生桌面验证实际交互和资源占用。
- 测试用短、自然的输入，允许用户逐步补充，不靠超长“防错提示词”替程序兜底。
- 审查拒绝不必然是程序错误，审查通过也不必然是科学正确。分别检查结果格式、保存、来源、具体判断及返修范围。
- 通用修复不强行迁移旧任务。只在新编译路线才能暴露的新工具/交互使用新任务验收；原任务能否采用新行为要看冻结契约，而非一概要求重建。
- 不自动代跑正式任务、不改库推进状态、不以有限证据授权替代真实结果检查。

## 2026-10-17：按问题提交与局部修正

### 同日补充：长响应首次失败的限时恢复

保留原 12 分钟失败累计预算，不改成无限等待。仅当同一逻辑请求的首个流已产生有效进展、持续至少一个预算时长，且可重试失败耗尽原预算时，允许唯一一次额外恢复。额外恢复从首次失败时起计，退避、建连、生成合计默认最多 12 分钟；即使不断收到增量也不能续期，再次失败不再开启重试循环。无进展首请求、永久错误、多次失败耗尽和用户取消不享受此例外。

普通成功长流仍不设总时长截止；恢复只重发未完成的模型请求，不重跑已完成工具，不接受缺终态的草稿，不自动继续正式旧任务。科研输出校验与内容修正次数完全独立，不放宽。

记录建连、等待、失败接收及其末尾无进展时间；提示以实际开始的请求次数为准，不把等待中的重试算成已发送。Responses 诊断补充完成项数量及缺失终态，不能凭 JSON 闭合推断成功。恢复超时在本地请求统计映射为 408 并保留 `MODEL_RECOVERY_TIMEOUT`，不冒充上游 HTTP 500。

### 问题级审查提交

具备问题跟踪与返修计划的审查，新模型接口将每条问题作为一个完整单元：稳定 `id`、当前判断和依据；open 条目内附 `correction` 与 `revision`，不再提交数字 `correctionIndex` 及顶层平行整改/计划数组。宿主仅确定性生成持久化索引和分类，原冻结输出、UI、返修按钮与科学校验保持不变，不猜缺失建议或历史状态。混填、歧义旧索引或孤立建议不能静默丢弃。

纠错优先 `reviewIssueReplacements`：完整替换指定稳定 ID 的问题，或补交宿主明确诊断的缺失历史问题，其他问题保留；顶层决定仅通过显式 `reviewUpdates` 修改。已有 quote-only 原文选段继续可用，同一问题不能同时完整替换和选段。模型仍可完整重交来新增实质问题/重组结论，但须承担完整检查，不自动批准。

内容修正默认两次。只有第二次成功合并局部补丁后，已知定位/状态说明/缺失 ID 问题集合严格缩小且无新增/其他错误，才允许一次额外修正；总上限三次，重复、倒退、格式失败和完整重交不增加预算。每次原始提交保留在日志，合并后的完整结果继续校验，失败不自动重跑阶段。

上下文先做无损优化：正文、当前证据和验收要求优先；完全重复来源可以引用同一输入中的文字，只有算上说明仍不增大才采用，原资料/历史/冻结哈希不变。首次提交直接选择原文、全面按需读取仍待开发；本轮不声称解决所有长上下文问题或真实模型误判。

## 2026-10-16 补充：搜索能力与提交协议

Exa MCP 默认随桌面启动后台连接，仅注册 `web_search_exa`，用于普通聊天和科研讨论的按需搜索；Jina 暂缓。不要把外部 MCP 连接状态/可变 Schema 变成每个冻结科研阶段的必需前提；后续阶段级接入应有稳定 Adapter 和离线退化，不热改旧任务权限。详情见 [网络与 MCP](NETWORK_BROWSER.md)。

同一次执行循环中，首轮预算后的阶段材料视图保持稳定，纠错只追加当前候选、诊断和实际提交接口，不因纠错内容变长再次分页。这样既保持同 run 实际用量指纹可复用，也避免提交接口关闭读取后把已经读过的正文改成 `$read`。首次仍预留提交/纠错余量，最终完整请求仍须通过预算；初始恢复的实现控制开销照常预留。此机制不改变持久化输入、引用身份、科学标准或修正次数，不承诺无限材料/任意大小纠错都能装入有限窗口。

审查/引用纠错不再向模型发送“完整结果属性 + 局部补丁属性”的混合 Schema。`submit_stage_result` 只描述完整结果，`submit_stage_repair` 只描述当前基线哈希与允许修改的单元；每轮仍只接受一次提交，合并后走完整原校验，实质性修改可完整重交，不替模型挑结论。瀑布流、用户重试/返修按钮与两次纠正预算不变。

证据综合的引用纠错也须拆开两种载荷：`citationAssessmentsPatch` 的单项只有 reference/supportingQuote，`citationQuoteSelections` 的单项只有 reference/sourceSegmentIds；不同引用可同时修，同一引用不能双写。未使用数组省略，传入的数组至少一项；`minProperties:2` 与必填 baseSHA256、禁止额外属性共同避免“仅哈希/空数组”在工具 Schema 通过、运行时才失败。该 keyword 只描述修正接口，不给科研输出新增验收条件。来源 ID 与连续范围仍由宿主精确校验，原文菜单只发一次；原始混填记录保留，不擅自替模型选择冲突载荷。耗尽提示区分引用修正提交格式与科研结论不合格；重试复用本轮已接受分组，不要求重传或从头开始。

原文选段还须与冻结摘录长度预算相容：每段展示 Unicode 字符数、从此段开始可选的最远连续终点和组合长度；更小限额下用含边界的独立 ID 细分，原文完整保留，不改共享审查选段身份、不重复全文枚举所有组合。长度安全只代表协议可提交，不证明支持科学判断；宿主仍拒绝超长、跨来源和跳段。超长反馈实际长度/上限/超出量，不再误报为字段混用。失败引文在同文档当前已提供候选的另一块中精确存在时，仅给引用定位导航；模型需完整重交更新引用及相关判断，宿主不得偷偷换块或拼接补全。

独立审查长字段引文不匹配时，纠错提交附上**当前版本、原字段路径**内的有限原文菜单（邻近段落一并保留）。`reviewBasisSelections` 选择已提供的片段，宿主按相邻字符范围带入连续原文；`reviewFindingsPatch` 只写文本值，两种数组可修不同单元，但不能覆盖同一单元或混用字段。菜单不是科学推荐、完整检索或缺失证明；相似度仅做同字段导航，不自动替换引文，不搜索历史充当当前依据。无合适片段时仍支持精确文本或完整重交。当前材料优先、历史意见后置且完整保留，不改变冻结输入与摘要；每轮菜单只发送一次，总量最多 12000 字符。正式科学判断和审查是否通过仍由完整审查负责，真实模型收敛需另行验收。

同一字段因多个问题分别生成的菜单只是相关片段导航，不是互斥证据权限。`pointer` 和 `inputSHA256` 都一致时，已提供的片段按同源复用；输出 `cell` 仍必须是已诊断单元，不因此允许改其他问题、来源或结论。同路径不同版本、不同路径相同文字均不能互借，选段还须相邻、限长且与原 pointer 一致。Schema 片段 ID 去重，不复制菜单正文或新增读取；结构正确但来源/范围选择错误应准确反馈选段问题，不能一律要求模型改提交字段。

原文导航与局部补丁资格解耦：引文与其他业务错误共存时只能完整重交，但仍提供当前原文菜单供精确摘录，不让模型退回翻找旧稿。所有依据错误一次反馈到具体输出单元，问题对应关系检查也不再只报前 8 处；错误清单不重复长引文和逐条通用指导，原文总量限制不因错误数量增长而放宽。有限菜单仍不等于完整按需材料读取。

首次专用提交和后续纠错共用同一个完整单 JSON 代码块解析规则（正文只是数据，仍须完整 Schema/业务校验）。只返回说明文字或伪工具文本时，在原两次内容修正额度内提示重交，保留已有候选、补丁基线、来源菜单和未解决诊断；失败原文必须先入审计。实际多工具/未授权工具调用、存储失败不进入内容纠正；不会执行伪工具、不额外增加重试额度、不把科学拒绝改成通过。
