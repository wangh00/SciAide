## 发布记录与现状分开

- [v1.0.3 发布说明](releases/v1.0.3.md)、[v1.0.1 发布说明](releases/v1.0.1.md)：只记录对应版本发布时的事实。
- [CHANGELOG](../CHANGELOG.md)：历史变更；不要把其中某次“本轮构建”当作最新状态。
- [PROGRESS.md](PROGRESS.md)：只维护一份当前进度和最近验证基线。
- `imgs/`：README 使用的界面截图，保留；截图不是最新界面或科学正确性的承诺。

## 维护方式

1. 改行为时更新对应专题和进度，不再往科研主文档逐轮堆叠修复日志。
2. “已实现”“自动化通过”“真实模型验证”“原生桌面验收”“已发布”分别表述；待验收项不能提前打勾。
3. 架构变更应记录决定、原因、代价、代码入口和重新评估条件，不把已被替代的设计继续列为当前规范。
4. 临时日志、截图、只读捕获和逐轮交接放在仓库忽略的 `.tmp/`；公共文档不携带用户任务内容、数据库路径身份或凭据。
5. 本次整理将旧 P0–P7 ADR 的有效决定合入系统架构与专题文档，删除被取代的阶段稿、旧 MCP 对照笔记及重复目录说明。原始历史可从 Git 查询；本地未提交版本另存于 `.tmp/docs-refresh-20261015/before/`，不再复制回文档目录。
