# AI 反馈与大学生英文改稿：小型证据地图

这是开发代理可自行推进的**在线科研流程测试输入**，不是预制科研结论或假模型夹具。当前执行结果只维护在 [开发进度](../../../docs/PROGRESS.md)，启动、权限、预算及敏感捕获边界只维护在[开发指南](../../../docs/development.md#科研流程调试入口)。

## 首次输入

> 请先讨论一个小型科研案例：AI 辅助反馈对大学生英文写作修订质量是否有帮助？限定 2021—2026 年，先明确综述范围；如果需要用户决定，请使用程序提供的结构化选择问题，不要编造论文或研究结果。本轮不要启动正式计算。

若模型提出范围选择，按真实问题语义回答，不依赖固定问题数、文案或选项 ID：

- 只看 ChatGPT/GPT、Claude、Gemini 等生成式大语言模型反馈，不把传统 AWE 单独混入。
- 人群为大学生，英文写作；观察真正发生的修订、修订稿质量或反馈采纳，不以满意度替代写作表现。
- 小型范围综述/证据地图，约 4—6 篇真实研究；优先可得全文，摘要材料明确标注。
- 主体约 800—1200 中文字；不声称穷尽检索，不汇总总体效应，不编造缺失的效应量或结果。
- 先准备路线，查看后显式采纳；讨论完成或有路线不等于科研完成。

## 代理自行推进

1. 新建独立空调试根，保存稳定 requestId，使用实际已配置模型；预先设置有限请求和会话时长。完整流程可能远多于一次问答，次数不等于金额或 token 上限，不自动加额度。
2. 经原问题回答接口回应；应恢复相同 Chat Run，不能凭空添加选项或换新讨论掩盖问题。
3. 检查路线与上述目标一致后显式采纳。Plan 模式的工具仍逐项审批；需要 full access 时须在该测试根和案例上都明确许可，不能在规划派生时偷偷提权。
4. 阅读真实候选题录/摘要再确认 4—6 篇；选文献是允许导入和审核，不是批准结论。不上传本例说明充当研究证据。
5. 核验导入类型、可读范围和引用。补充全文时保留旧附件与执行历史，通过原材料/引用更新链接管，不让过期输入继续生成整稿后才作废。
6. 到引用确认点时检查原文和范围；只在仍符合最初小型地图目标时明确接受有边界的有限证据。不使用“无引用继续”掩盖已存在的引用问题，不自动批准独立审查。
7. 报告应使用可读中文，区分摘要与全文、配对前后比较与受控试验、混合反馈与单独 AI 效果。来源、限制和审查均保留。
8. 仅 `workflow_completed` 且原交付门禁通过才记为流程完成；人工确认、暂停、讨论 completed 或 CLI 退出码 0 都不算。

## 首个失败如何记录与修复

- 保存当前阶段、冻结输入/Schema、原始模型提交、实际诊断及模型次数，先读状态，未知结果不盲重发。
- 格式错误先从完整根 JSON 校验；有 summary 却被报缺失时，检查是否误选内部片段，不增加修正次数掩盖错误。
- 引文长度、来源不匹配、题录冒充结果等仍按原标准检查；不自动截断摘录或替模型修改科学判定。
- 程序问题先以本机 HTTP/临时 SQLite 或只读捕获回放复现、修复，再在授权范围内显式重试本案例。上游额度、拒绝、预算/时限或真实科学否决如实记为停止，不改历史为成功。
- 正式用户任务不因本例被恢复、重建或重传资料；原生桌面渲染与领域科学质量另行验收。
