# 从界面测试连续数据分析

这是人工构造的演示数据，不是真实科研样本。它用于检查界面、计算和版本续接，不用于检验科学结论。

1. 在程序选择项目及模型，顶部进入 **科研模式** → **研究方案**。点“数据分析”的“填入示例”只会编辑问题，不会计算；也可以直接输入：

   > 我有一张 CSV 表，字段 id 为记录编号、group 为分组标签、x 和 y 是演示数值。请规划数据分析路线，不检索文献，不做显著性检验或因果推断。采用路线后我会选择数据。计算行数、x 与 y 的合计及各组均值，绘制 x-y 散点图，交付代码、结果表、图形和解释；不要用文本猜算代替 Python 执行。

2. 点 **生成研究路线**。若询问数据/目标，按实际情况回答；查看包含数据预检及 Python 计算的路线，点 **采用并补充数据**（标签依实际可用性显示）。
3. 在聊天流出现的设置卡中，点 **添加数据文件**，选本目录 `initial.csv`；检查 Python 环境，点 **开始执行所选路线**。文献选择器不是表格计算入口。
4. 等待执行及审查。应能查看结果与本次生成文件。校核：6 行，x 合计 21，y 合计 48；A 组 x 均值 2 / y 均值 5，B 组 x 均值 5 / y 均值 11。具体文件名、解释和图形格式由实际路线决定。
5. **先不要登记产物**。在同一任务的原聊天框，用回形针添加 `updated.csv` 并实际发送：

   > 用这次上传的 updated.csv 替换当前数据，不是追加合并；下一版只使用 updated.csv。保持原方法与输出，先给出列明完整数据集合、沿用阶段和重算范围的方案，等我确认后重算；保留旧数据和旧结果。

6. 确认卡应明确列出新文件，原文件不在新计算集合中。**确认前**仍是 6 行 / 21 / 48；点 **确认方案并开始返修** 后应为 8 行 / 36 / 80。A 组均值不变，B 组 x 均值 6 / y 均值 13。如果卡未列文件，不要确认；让 AI 读附件后重提方案。
7. 再发送“只解释为什么结果变化，不修改、不重新执行”。应只讨论，不新增计算执行。可继续讨论另一种方法；真正改方法仍先看确认卡。

测试这套新版执行能力建议新建科研任务（不需要新建 Codex 聊天），避免旧冻结路线缺少历史读取工具。已登记产物的原任务暂不支持确认返修，不要为了测试删除已有成果。

## 文献比较入口

同一“研究方案”页面点 **文献比较**，用下方 **添加本地文献** 选择自己有权使用的 PDF/文本资料，调整问题后 **生成研究路线**。路线与证据选择确认、比较稿仍在原聊天流，不存在另一个“文献比较工作台”。这只是示例，不能保证真实模型必然生成正确比较。

建议明确两篇或三篇文献、具体比较问题与交付字段，并要求原文定位；不要仅写“做个比较”。完成后先不登记，在原聊天框添加补充论文并发送，要求先讨论异同、提出列明文件的更新方案，确认后再补证。不要把摘要或未找到的片段当成已读全文。
